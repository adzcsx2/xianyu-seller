# Backend API-First Rule

Apply this rule before business-capability, data-access, integration, diagnosis, acceptance, or new-endpoint work.

1. Translate the request into domain, resource, action, and caller/identity keywords.
2. Search the project index first. Rebuild it if missing or stale:
   `pwsh -File .ai/tools/api-first/build-api-index.ps1 -WorkspaceRoot .`
   then use `search-api-index.ps1` with a natural-language query.
3. Verify every candidate in source: route registration, handler, Pydantic/request/response schema, service or repository flow, and authentication/authorization dependency. Code is authoritative; docs and OpenAPI are secondary.
4. Report the method/path, caller boundary, relevant inputs/outputs, and exact source evidence. Treat `auth_hint` as a discovery clue only.
5. Reuse a safe verified match. Propose a new public contract only after the search and direct source inspection show that no existing endpoint fits.

## 全量接口目录

每次 API-first 检索前，先阅读同目录的 [05-全量接口目录](./05-全量接口目录.md)。该目录以运行时 OpenAPI、源码 handler 和静态索引的交集为执行参考，逐条记录完整路径、handler/source、认证与归属、请求/响应 schema、错误和副作用。

特别注意：`POST /items` 只写入当前用户的本地商品记录（`source=manual`），不是闲鱼发布接口；当前项目没有经源码验证的闲鱼商品创建/发布 API。素材字段、商品 ID 回写和自动化修复接口不能推断出外部发布能力。

Searching and inspection are read-only. They do not authorize calling a state-changing endpoint, exposing an admin/user-scoped endpoint to another caller, or changing the public API without a plan.
