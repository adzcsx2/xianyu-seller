# 知识库 AI 问答与新增问答保存 — TDD 证据

## 来源与用户旅程

- 来源：2026-09-08 用户反馈，以及运行中容器的请求日志。日志确认两次失败请求均为 `POST /knowledge-bases/{id}/qa-entries`，状态码 `422`。
- 旅程：打开任一知识库详情后，可使用页面顶部所选账号现有的 DeepSeek 配置，只针对当前知识库提问。
- 旅程：新增公开问答时不需要手工填写内部键，保存后系统自动生成稳定键。
- 旅程：配置无效或服务调用失败时，页面显示后端业务错误，而不是泛化的 `Request failed with status code 422`。

## RED

- 定向测试覆盖空问答键、当前知识库隔离、账号配置选择、提示词内容隔离和前端入口。
- 旧实现结果：空问答键返回 `422`；问答路由返回 `405`；AI 引擎缺少知识库问答方法；前端缺少对应交互。
- 检查点：`de08d53 test: 复现知识库问答与新增条目422`。

## GREEN 与重构

- 后端新增 `POST /knowledge-bases/{base_id}/ask`，使用所选账号现有 AI 配置并只加载被点击的知识库。
- 发送给模型的内容限定为已启用的买家可见事实、公开问答及全部内部规则；停用内容、来源备注和其他知识库不会进入提示词。
- 新增公开问答时，空 `qa_key` 自动生成为 `qa-{12位十六进制}`；前端不再要求用户编辑内部键。
- API 错误解析支持 FastAPI 字符串、对象和数组详情，页面能显示可操作的错误原因。
- GREEN 检查点：`edfe487 feat: 增加知识库问答并修复问答保存`。
- 边界测试/重构检查点：`38715ae test: 补强知识库问答异常与长度边界`、`ec281a7 test: 覆盖知识库问答配置错误`。
- 自审发现最初仅加载 `model_instruction`，先新增失败测试 `8d6908c test: 复现知识问答未应用业务规则`，再由 `3e1bd5a fix: 让知识问答应用全部业务规则` 修复为价格、议价、固定回复、拒绝、输出约束和模型指令均参与问答。
- 后续代码审查发现知识库问答误用了买家自动回复的 300 字清理器，并且提示词对内部规则能否作为答案依据存在冲突。RED 检查点 `04caa93 test: 复现知识问答截断与规则依据冲突` 同时复现两项问题。
- GREEN 检查点 `75d8ec9 fix: 保留完整知识问答并消除规则提示冲突` 改用问答专用清理器，保留完整多行答案，并明确知识数据与内部规则均可作为回答依据；`46661ef test: 覆盖知识问答清理安全边界` 补齐思维链和非文本返回分支。
