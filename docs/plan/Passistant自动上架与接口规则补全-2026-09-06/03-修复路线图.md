## 1. 问题分级

| 优先级 | 问题 | 当前影响 | 目标 |
|---|---|---|---|
| P0 | 唯一已发布商品尚未与唯一账号做 API 归属确认 | 无法安全绑定库存和 AI | 登录、同步并唯一定位 `1081710901648` |
| P0 | 100 个生产码已生成但尚未完成导出/数据库核验 | 重生成会重复；直接导入可能带入错误集合 | 禁止 Generate，完成三命令与集合核验 |
| P0 | D card 和专属发货尚未配置 | 已发布商品不能自动发货 | 幂等创建/复用一个 card，绑定每单 1 码 |
| P1 | 根 `.env` 配置尚未应用到账号 AI 设置 | 自动回复仍可能未启用或使用旧配置 | 安全读取后 PUT，并完成五类隔离测试 |
| P1 | 静态索引 221 与先前 runtime 220 不一致 | AI 可能检索到注释 route 或错误验证码路径 | 修生成器并加一致性测试 |
| P1 | 缺少单文件全量 API AI 规则 | 新模型容易误判素材字段为发布能力 | 生成 `05-全量接口目录.md` |
| P2 | 旧计划仍要求实现/调用发布 API | 会制造第二商品并扩大范围 | 完全移除发布、图片上传和 publisher 路线 |

## 2. 阶段路线

### 阶段 1：登录、同步和唯一商品归属

1. 只读 API 登录并读取账号、商品、card、AI 基线。
2. 仅在需要时同步 owned/enabled 账号的已有商品。
3. 核验唯一 item、价格和状态，不编辑或发布。

门禁 M1：`1081710901648` 恰好属于一个当前用户启用 `cookie_id`，价格为 ¥9.9。缺失或歧义 blocked。

### 阶段 2：既有卡密、D card 和自动发货

1. 只读 QueryBatch/ListCodes/ValidateExport，核验 TXT/CSV/hash/suffix。
2. 复用完全一致 card，或只创建一次。
3. 保存/回读普通单规格、每单 1 码配置。

门禁 M2：批次、TXT、CSV、D card 四方恰好 100 且集合一致；delivery `configured=true`、`complete=true`。

回退：校验失败停止写入，精确 DisableBatch preview；明确授权后禁用 remaining available inventory。绝不补生成。

### 阶段 3：从 .env 应用 DeepSeek

1. 只读根 `.env` 必需键存在性与账号当前设置。
2. 使用环境 Key/模型/地址，保存账号设置和商品提示词。
3. 回读 `api_key_configured=true` 并运行五类隔离测试。

门禁 M3：账号非敏感字段与环境安全比较一致，五类回复符合合同。失败时不自动换模型/地址。

### 阶段 4：接口规则和总验收

1. 只读重审 runtime/index/source/frontend。
2. 先写失败测试，再修索引器。
3. 生成覆盖全部 runtime operation 的单一 AI 规则。
4. 完整测试和 API-only 最终回读。

门禁 M4：runtime/index/MD 三套 `METHOD PATH` 集合相等；Python 全套和 `git diff --check` 通过；商品/card/delivery/AI 状态可回读。

## 3. 依赖关系

```text
M1 唯一 cookie_id ↔ 已发布 item
  ↓
M2 已验证 100 码 → 唯一 card → 每单一发货
  ↓
M3 根 .env → 账号 DeepSeek 设置 → 五类测试
  ↓
M4 API 目录可信 + 总验收
```

所有阶段串行。card 依赖明文集合；发货依赖 card ID；AI 依赖唯一 cookie；最终目录依赖最终源码。

## 4. 写入预算

| 写入 | 条件 | 最大次数 |
|---|---|---|
| `POST /items/get-all-from-account` | 目标 item 尚未唯一出现 | 每候选账号 1 次 |
| `POST /cards` | 不存在完全一致 card | 1 次 |
| `PUT .../delivery-config` | 现有配置不等于目标 | 1 次 |
| `PUT /ai-reply-settings/{cookie_id}` | 当前设置不等于目标 | 1 次 |
| `POST /ai-reply-test/{cookie_id}` | 设置回读完整 | 5 次隔离问题 |

禁止：`POST /items`、商品发布/复制/删除/编辑、图片上传、Generate、真实订单或买家消息。

## 5. 阻断矩阵

| 条件 | 立即动作 | 禁止动作 |
|---|---|---|
| 无安全密码或登录失败 | blocked，向用户索取 | 浏览器取 token、猜密码 |
| 多账号/多商品归属 | blocked，列非敏感候选 | 自动选第一项 |
| 同步后 item 缺失 | blocked | `POST /items` 伪造 |
| 商品价格/状态不符 | blocked，用户确认 | 创建第二商品 |
| 导出缺失/集合不一致 | 停止销售链，精确禁用 preview | Generate/补码 |
| card 部分匹配 | blocked | 修改旧 card 或新建第二 card |
| delivery 不完整 | blocked | 用通用规则掩盖 |
| .env 必需键缺失 | blocked | 猜 Key/模型/地址 |
| AI 测试失败 | 记录安全错误并 blocked | 自动换配置或泄露请求 |
| 索引差异 | 修测试/生成器 | 手工删条目 |
| 前端未改 | build 记 not applicable | 虚报构建通过 |

## 6. 完成定义

- 唯一商品与唯一 owned/enabled `cookie_id` 关联；
- 已生成批次和导出验证，D card 恰有同一 100 个码；
- 发货配置完整、单规格、每单 1；
- 根 `.env` 的 DeepSeek 配置已安全应用，五类隔离测试通过；
- 全量接口目录覆盖最终 runtime，索引差异为零；
- 没有第二商品、重复批次/card、秘密泄露或浏览器/DB 绕行。

## 7. 不属于本路线的事项

闲鱼商品发布/编辑、自动下架、真实订单消费测试、Passistant 发版、Git push/部署、新增 `docs/README.md`。需要时另立请求。
