# 开发规范

[返回 README](./README.md) · [上一篇：架构设计](./01-架构设计.md) · [下一篇：修复路线图](./03-修复路线图.md)

## 1. 适用范围与事实源

适用于后续模型执行本计划时对 `D:\github\xianyu-super-butler` 的代码、规则文档和运行 API 操作，以及对 `E:\exilecore2\Passistant` 激活码批次的只读核验。

事实优先级：运行时 OpenAPI/源码 → Passistant 卡密技能/脚本结果 → 已认证 API 回读 → 本计划 → 旧 README。冲突以高优先级为准，无法验证写 `unknown`。

## 2. 通用执行规则

- 每一步先读当前状态，再决定是否写；写后立即回读。
- 所有步骤串行，不使用并行组。
- 只修改请求直接需要的文件，保留用户未提交改动。
- API 记录方法、路径、状态码、资源 ID 和数量摘要，不记录秘密。
- 不把单次 2xx 当作完成；以回读字段和集合一致性为证据。
- 不 push、不开 PR、不改远程、不发版。
- 阶段提交只做本地提交，并仅暂存本任务文件。

## 3. 认证与秘密

- 用户名为 `admin`，密码来自安全会话上下文；登录只用 `POST /login`。
- 根 `.env` 是 DeepSeek `API_KEY`、`MODEL_NAME`、`MODEL_BASE_URL` 的输入源。
- 不读取浏览器 `localStorage`、Cookie 存储或开发者工具状态。
- 不在 Markdown、源码、fixture、命令回显或日志中写 password、token、Cookie、API Key 和完整激活码。
- 安全解析 `.env` 时默认只输出“存在/缺失”布尔值。模型/base URL 也只在进程内比较，除非用户明确要求展示。
- 未来会话若没有密码，必须 blocked 并向用户索取。
- 不修改 `.env`；把其中非空 Key/模型/地址通过账号 AI 设置 API 应用。

## 4. 商品与账号规范

- 唯一商品 ID：`1081710901648`。
- 只接受当前用户拥有且启用的唯一 `cookie_id`。
- `GET /items` 已唯一命中时跳过同步；否则用 `POST /items/get-all-from-account`。
- 禁止调用 `POST /items` 解决同步失败。它只写 `source=manual` 本地记录，不会发布。
- 禁止实现 publisher、素材 create/publish、发布任务、发布按钮、图片上传或第二商品逻辑。
- 不用本地 PUT 假装闲鱼商品已被编辑；不擦亮、删除、下架或改图片。
- 商品价格必须可验证为 ¥9.9；支持国际服/台服，不支持国服。

## 5. 激活码规范

```text
batch_no: XYB-PASSISTANT-30D-20260906-1081710901648
quantity: 100
duration_days: 30
channel: xianyu
generation_audit_count: 100
```

- 使用 `pwsh.exe` 执行 `Manage-ActivationCodes.ps1`。
- 后续只允许 `QueryBatch`、`ListCodes`、`ValidateExport`；禁止 `Generate`，包括 preview。
- 明文只从现有 TXT/CSV 读取，不能从 hash-only 数据库恢复。
- 在进程内验证数量、唯一性、集合、batch、duration、hash 和 suffix。
- 输出不得出现完整码；报告只写数量、摘要和文件元数据。
- 导出必须保持 Git 忽略/未跟踪。
- 校验失败时停止 D card/delivery；先精确 `DisableBatch` preview，只有明确授权后才 `-Execute`。
- 不禁用已兑换码，不逆转会员时间，不删除审计事件。

## 6. 卡密库存规范

先 `GET /cards`，候选再 `GET /cards/{id}`。复用必须同时满足当前 user、完整批次号、`type=data`、enabled、`is_multi_spec=false`、100 个非空行且与 TXT 集合相等。

不存在时才调用一次 `POST /cards`：

```json
{
  "name": "Passistant 30天月卡-1081710901648",
  "type": "data",
  "data_content": "<仅在进程内填入验证后的100行>",
  "description": "batch=XYB-PASSISTANT-30D-20260906-1081710901648; duration_days=30",
  "enabled": true,
  "delay_seconds": 0,
  "is_multi_spec": false
}
```

禁止打印 request body。部分匹配、多个候选或集合不一致时 blocked，不 PUT 修补，也不新建第二 card。

## 7. 自动发货规范

写前 GET，相等则跳过 PUT：

```json
{
  "enabled": true,
  "is_multi_spec": false,
  "variants": [
    {
      "display_name": "Passistant 30天月卡",
      "spec_text": "30天",
      "spec_payload": null,
      "platform_sku_id": "",
      "card_id": "<唯一真实card_id>",
      "delivery_count": 1,
      "enabled": true,
      "binding_enabled": true,
      "source": "manual"
    }
  ]
}
```

路径为 `PUT /items/{cookie_id}/1081710901648/delivery-config`。完成必须 GET 证明 `configured=true`、`complete=true`、`variant_count=1`、`configured_count=1`、`delivery_count=1` 和正确 card ID。

不得用通用规则补偿专属配置失败，不创建真实测试订单消费卡密。

## 8. DeepSeek 配置规范

从根 `.env` 读取并直接用于 PUT：

- `api_key = API_KEY`；
- `model_name = MODEL_NAME`；
- `base_url = MODEL_BASE_URL`。

不得在文档或输出展开值。其余字段固定：

```json
{
  "ai_enabled": true,
  "user_agent": "",
  "max_discount_percent": 0,
  "max_discount_amount": 0,
  "max_bargain_rounds": 1,
  "context_enabled": true,
  "context_message_limit": 12,
  "context_expire_minutes": 120
}
```

`custom_prompts` 是 JSON 字符串，解析后恰有：

- `default`：产品、30 天 ¥9.9、国际服/台服、国服不支持、每单一码、下载与兑换；只回答当前问题，不虚构订单状态。
- `price`：固定价 ¥9.9/30 天，不接受砍价；不承诺优惠、赠送或退款。
- `tech`：官网 `https://passistant.vip`、Windows x64、管理员运行 `Launcher.exe`、注册/登录、个人中心兑换；故障时索取错误信息或转人工。

共同安全边界：

```text
不要声称已确认付款、已有库存、已发货或已退款，除非上下文提供可验证订单事实。
不要承诺绝对安全、零封号、官方授权或百分之百兼容。
针对当前问题简短回答；不知道时明确需要订单号、截图或人工核查。
```

GET 的 `api_key` 始终为空，以 `api_key_configured=true` 证明已保存。用户已授权以根 `.env` 为准，所以 P3.2 可用非空 Key 覆盖账号旧 Key，但不能输出请求体。

## 9. API 索引生成器规范

修改 `.ai/tools/api-first/build-api-index.ps1` 时：

- 保持 `Set-StrictMode` 和失败即停；
- decorator 只在实际代码行解析，跳过注释；
- 解析 `APIRouter(prefix=...)` 和 `include_router` 前缀；
- handler 绑定 decorator 后的稳定函数符号；
- 可验证时补 request/response schema；
- auth/owner 从 dependency/handler 验证，不能只按路径猜；
- catch-all converter 只对确认 handler 规范化；
- 排序确定，连续生成两次集合一致；
- 不因目录期望而增加业务 route。

## 10. 全量接口目录规范

`docs/references/ai-rules/05-全量接口目录.md` 覆盖每个 runtime operation，表头建议：

| Method | Path | Handler / Source | Auth / Owner | Request | Response | Errors | Side effect |
|---|---|---|---|---|---|---|---|

完整 path；handler 用符号/源文件；auth 区分公开、可选、当前用户、管理员和 unknown；副作用区分只读、内存会话、数据库、外部网络、文件；关键错误从源码总结；未知写 `unknown`。

必须明确 `POST /items` 仅本地记录、当前没有商品发布 API，并更新 `03-后端接口优先.md` 路由到该文件。

## 11. 测试规范

- 先写在旧索引器上稳定失败的测试，再修生成器。
- Python 全套：`python -m unittest discover -s tests -p "test_*.py"`。
- 索引：`pwsh.exe -File .ai/tools/api-first/build-api-index.ps1 -WorkspaceRoot .`。
- 专用测试名先用 `rg --files tests` 发现，不能虚构。
- 前端未改时不运行 npm build，记 `not applicable`；有变化才运行 `npm ci` 和 `npm run build`。
- 最后 `git diff --check`。
- 单元测试不调用真实闲鱼、DeepSeek 或生产数据库；生产只做受控 API/脚本操作。

## 12. 禁止规则

- 禁止再次生成激活码。
- 禁止发布、创建、复制、编辑或删除闲鱼商品。
- 禁止浏览器、Playwright、桌面自动化和直接数据库写入。
- 禁止把 `POST /items` 描述为发布接口。
- 禁止打印密码、token、Cookie、Key 或完整卡密。
- 禁止遇到歧义时选择第一项。
- 禁止手工编辑索引/目录掩盖生成器错误。
- 禁止修改根 `.env`。
- 禁止新增依赖、迁移、publisher 或发布状态机。
