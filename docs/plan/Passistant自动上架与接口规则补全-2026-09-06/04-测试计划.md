## 4. 测试策略

### 4.1 认证与商品唯一性

`POST /login` 后用 GET 确认 user/admin、owned/enabled 账号与 item 出现次数。只在未唯一命中时同步，每次后重新统计。调用清单必须没有 `POST /items`、publish、图片或商品编辑写入。核验价格 `9.9` 和可售状态。

### 4.2 前端功能审计

静态读取 `ItemList.tsx`、`ProductAutomation.tsx`、`services/api.ts`，建立按钮/handler/API/副作用矩阵，证明手动添加只写本地、同步只拉已有商品、擦亮不创建商品、专属/通用发货与保护/card/素材规则都有现有 API，并且不存在 publish 请求。不用 Playwright/浏览器。

### 4.3 既有激活码批次

```powershell
pwsh.exe -File .agents/skills/manage-activation-codes/scripts/Manage-ActivationCodes.ps1 -Action QueryBatch -BatchNo XYB-PASSISTANT-30D-20260906-1081710901648
pwsh.exe -File .agents/skills/manage-activation-codes/scripts/Manage-ActivationCodes.ps1 -Action ListCodes -BatchNo XYB-PASSISTANT-30D-20260906-1081710901648
pwsh.exe -File .agents/skills/manage-activation-codes/scripts/Manage-ActivationCodes.ps1 -Action ValidateExport -BatchNo XYB-PASSISTANT-30D-20260906-1081710901648
```

验证 batch quantity/duration/channel/status、100 条 metadata、TXT/CSV 各 100 且集合相同、hash/suffix 对应、D card 集合相同。完整码只在进程内比较。任何失败都不得 `Generate`。

### 4.4 Card 与发货

- 无候选：创建一次后 GET。
- 完全一致：复用，不 POST。
- 部分一致/多个：blocked。
- delivery 写前 GET；相同不 PUT。
- 写后断言 configured/complete/variant/card/delivery_count。
- 不创建真实订单、不消费卡密；并发领取由现有单元测试覆盖。

### 4.5 DeepSeek

安全解析根 `.env`，不输出值。账号 PUT 后 GET，断言 `api_key_configured=true`，模型/base URL 在进程内与环境一致，上下文 12/120、折扣 0/0、议价 1、三个 prompt 完整。

五类 test API：

1. 价格/砍价 → 30 天 ¥9.9 固定价。
2. 国服/台服 → 国服不支持，国际服/台服支持。
3. 下载激活 → 官网、管理员启动、登录、个人中心兑换。
4. 风险 → 不作绝对承诺。
5. 无订单事实的付款未发货 → 不虚构，索取订单信息/人工核查。

### 4.6 API 目录一致性

构造 `runtime`、`index`、`docs` 三个 `METHOD PATH` 集合并断言相等、无重复。重点：注释 verify-all 不存在；七条 captcha router route 有完整前缀；manual-session 不重复；catch-all 正确规范化；handler/source 可定位；未知 auth/schema 明示；`POST /items` 标为本地写入；没有发布 operation。

### 4.7 API-only 最终冒烟

最终 GET 回读 user/account/item/card/delivery/AI。审查调用清单没有浏览器/Playwright/桌面、D SQLite 写命令、Generate、`POST /items`、publish、图片上传、商品删除/编辑，且写入不超过预算。

## 7. 退出条件

### PASS

- 唯一 item/cookie 和 ¥9.9 可回读。
- batch/TXT/CSV/card 的 100 码集合一致。
- delivery complete、单 variant、每单 1。
- DeepSeek 环境配置已应用，五类测试通过。
- runtime/index/docs route 集合相等。
- 聚焦测试、Python 全套和 `git diff --check` 退出 0。
- 调用清单无禁止操作或秘密输出。

### BLOCKED

密码不可用/登录失败；账号或商品歧义；同步后 item 缺失；价格/状态不符；导出或码集合不一致；card 部分匹配/重复；delivery 不完整；环境 AI 键缺失；AI 提供方连接/模型失败；OpenAPI 不可用；用户改动导致无法隔离的测试失败。

### 允许的 `not verified` / `not applicable`

真实付款/订单消费测试可 `not verified`；前端未修改时 build 为 `not applicable`。不能用于掩盖商品归属、码集合、发货、AI 隔离测试或 API 目录差异。

## 8. 清理与恢复

已发布商品和已生成批次都不是测试数据，不删除、不重生成。校验失败只做精确禁用 preview，执行需符合技能授权。新 card/正确 delivery/AI 配置不因后续文档测试失败而回滚；记录并修复对应代码/文档。
