## 恢复协议

1. 读取进度指针，确认当前 Phase、状态、`next_action` 和 blockers。
2. 跳到对应 Phase 清单，从第一个未勾选的 `P<N>.<M>` 开始。
3. 完成一个任务后立即勾选，更新进度指针，并在执行日志顶部追加一条脱敏记录。
4. 一个 Phase 的全部任务和验收条件通过后，主执行代理才可切换 Phase。
5. 遇到阻断时把状态设为 `blocked`，记录精确证据、影响和恢复条件，然后停止。
6. 进度指针、Phase 切换、产品意图冲突、运行数据写入和最终审计只能由主执行代理处理。
7. 工作区已有用户修改。不得 reset、checkout、覆盖或批量格式化；与 `app/reply_server.py`、`scripts/run_tests.py` 等重叠时逐 hunk 核对，无法区分就记录 blocker。

## 不可变约束

- 知识内容、原始文档正文、来源备注和真实运行数据都是私有业务数据，不得复制进文档、fixture、日志、提交信息或外部服务。
- 文档上传只接受用户主动选择的本地 `.md`、`.markdown`、`.txt`；不根据引用字符串读取服务器路径，不下载 URL，不扫描仓库。
- 上传、解析与导入是三个可观察状态。上传或解析成功不代表知识已进入 AI；只有用户确认导入且条目启用后才可进入现有事实检索。
- 来源元数据和备注继续不进入模型。问答或预览只返回安全的标题/章节依据摘要，并明确标注为“提供给 AI”，不宣称模型一定采用。
- 首版不增加 PDF/DOCX/OCR、向量数据库、embedding、外部解析器、网页抓取或第二数据库。
- 所有内部稳定键由服务端生成。普通用户界面不得要求填写或理解 `fact_key/source_key/rule_key/qa_key`。
- 文档导入必须单事务、单次递增知识库 version。失败后文档、来源、事实和导入关系不能出现部分提交。
- 同一知识库同一 SHA-256 内容重复上传是幂等命中，不新增重复文档、不递增 version。
- 认证沿用现有 `get_current_user`；全局知识库仍不新增 owner/RBAC，商品预览继续校验 cookie/item scope。
- 删除被引用来源或文档默认拒绝并返回分型 409 与关联摘要。不得静默清空 `source_ids` 或留下悬空关系。
- 订单事实、秘密保护、商品绑定和引擎硬安全不因文档能力而改变。
- 实现采用 RED → GREEN；完整验收使用 `python scripts/run_tests.py`，不把手工点击或桌面控制作为必要门禁。
- 不 push、不建 PR、不改 remote；是否本地提交另按用户要求和仓库规则处理。
