# 修复路线图

[返回 README](./README.md) · [上一篇：开发规范](./02-开发规范.md) · [下一篇：测试计划](./04-测试计划.md)

## 1. 路线图原则

本计划按“先冻结可观察合同，再建立数据原子性，然后开放 API，最后交付 UI 与发布门禁”推进。阶段不得倒序：没有文档状态与事务保证时，不先做上传按钮；没有安全依据合同，不先展示“引用”结论。

## 2. 优先级

| 优先级 | 问题 | 影响 | 对应阶段 |
| --- | --- | --- | --- |
| P0 | 标题被误认为真实文件/AI 引用 | 用户无法判断知识是否生效 | Phase 1–3 |
| P0 | 上传/导入无原子和隐私边界 | 可能部分写入或泄露私有文档 | Phase 1–3 |
| P1 | 来源 in-use 误报版本冲突 | 用户无法删除或恢复 | Phase 3–4 |
| P1 | 事实/来源/规则要求内部 key | 普通用户无法可靠创建 | Phase 3–4 |
| P1 | 绑定请求竞态 | 可能显示/操作错误商品 scope | Phase 1、4 |
| P1 | core 测试静态 assets 夹具阻断 | 无法形成可信发布门禁 | Phase 5 |
| P2 | PDF/DOCX/OCR/远程同步 | 非首版明确需求 | 后续独立计划 |

## 3. 依赖图

```text
Phase 1 合同与 RED
        │
        ▼
Phase 2 parser + schema + 原子导入
        │
        ▼
Phase 3 API + usage + evidence + 自动 key
        │
        ▼
Phase 4 UI 向导 + 校验 + 竞态/错误恢复
        │
        ▼
Phase 5 测试夹具 + E2E + quality + 文档/迁移验收
```

不存在安全的跨阶段并行组。Phase 内多个任务也共享 schema/version/DTO，默认串行；若执行者后续希望并行，必须先证明文件和接口无共享并更新进度指针，但最终 Phase 切换仍由主代理串行确认。

## 4. Phase 1：合同与红灯

### 目标

把当前“没有文档能力”“无法判断真实引用”“普通用户需要内部 key”“409 误导”“scope 请求竞态”变成可重复测试，而非依赖截图或主观判断。

### 交付物

- 合成文档解析测试。
- DB/API 合同测试。
- 运行时依据与来源隔离测试。
- 前端合同与竞态测试。
- 当前工作区、API index、定向测试和完整 core 阻断的脱敏基线。

### 门禁

- 新测试必须因为缺少能力而 RED。
- 旧知识库相关测试继续可运行，不能因 fixture/import 崩溃产生假红。
- 不改运行数据库，不复制私有知识正文。

### 回退

Phase 1 只增加测试和证据。若合同理解被纠正，修改 RED 测试即可；不得为让旧实现通过而降低用户需求。

## 5. Phase 2：数据与事务底座

### 目标

在任何公开上传 UI/API 之前，先建立确定性 parser、文档/章节/import 模型、旧来源兼容和可恢复 mutation。

### 顺序

1. 幂等 v3 schema 与兼容投影。
2. 纯 parser。
3. 文档/usage 读模型。
4. 多章节原子导入。
5. 删除、占用和回滚。

### 里程碑 M1：本地文档闭环可由 Python 调用

满足：合成 Markdown 经 parser 保存为 document/sections/source；选定章节后只创建 facts 和 imports；重复、冲突和失败不产生多余行。

### 门禁

- temp DB 上 schema 重复初始化 no-op。
- parser 单测全绿，且模块无 HTTP/AI/文件路径读取。
- 事务失败前后 base version 和所有相关表一致。
- 旧 source 全部保持 `metadata_only`，无猜测迁移。

### 回退

新表/列前向保留，旧应用可忽略。数据异常时从 runner/运维备份恢复，不 DROP 旧表、不手写逆向清理 live DB。

## 6. Phase 3：API 与可验证依据

### 目标

把底层能力变成严格、可发现、可分型恢复的认证 API，并使 UI 能准确展示关系与模型上下文证据。

### 顺序

1. 稳定 error code。
2. 文档 list/upload/detail/import/delete routes。
3. usage/status 投影。
4. `provided_evidence`。
5. 四类公共 CRUD 自动 key。

### 里程碑 M2：API 完整但尚未开放 UI

满足：TestClient 可以完成全旅程；OpenAPI 有明确 multipart/JSON schema；来源正文/notes/路径不出现在模型 messages 或安全 response。

### 门禁

- 认证、feature flag、404、409、413、415、422 都有测试。
- error code 与前端恢复动作一一对应。
- evidence 集合与实际纳入上下文的 content id 集合一致。
- 公共创建 request 不接受 key；seed/migration key 回归稳定。
- API index 从源码重建并能检索新 endpoints。

### 回退

feature flag 关闭所有新写接口。旧知识 CRUD/绑定继续工作；新增表保留。若 evidence 有缺陷，可暂时返回空数组而不能返回猜测来源。

## 7. Phase 4：普通用户体验

### 目标

让非 AI、非工程用户不接触 key、路径、JSON 和版本细节，也能理解“文件是否上传、是否导入、哪些条目关联、问答拿到了哪些依据”。

### 顺序

1. 先修 scope stale response，避免在错误商品上操作。
2. 增加文档工作区与上传—预览—导入向导。
3. 增加来源状态/反向关系。
4. 增加问答/预览依据。
5. 隐藏 key、补行内校验。
6. 分型处理冲突与删除。

### 里程碑 M3：普通用户旅程可完成

用户在同一个编辑器内完成：上传合成 README → 看章节 → 确认买家可见 → 导入 → 看关联数量 → 提问 → 看“本次提供给 AI 的依据”。

### 门禁

- 上传前和导入前含义清晰；上传不等于生效。
- 三种“添加”动作名称不混淆。
- 旧来源即使标题像文件名，也显示未上传。
- 无效表单不发 API 请求，错误定位到字段。
- 延迟旧请求不能覆盖新 scope。
- 每个 409 error code 有不同恢复行为。
- TypeScript 和 detached Vite build 通过。

### 回退

若 UI 发布需回退，新后端 API/数据保留且 feature flag 可关闭。不要删除已经导入的事实；它们仍按现有知识运行时工作。

## 8. Phase 5：可信发布门禁

### 目标

先修复当前 core 测试因 `frontend-static/assets` 缺失导致的同源错误，再完成无头 E2E、全量质量、迁移/回滚和文档一致性。

### 顺序

1. 最小修复测试静态目录夹具；保留生产 mount 失败语义。
2. 新增知识库无头 E2E 并注册到 runner。
3. 定向 → core snapshot → E2E snapshot → quality snapshot。
4. temp DB 迁移、失败注入、恢复和隐私扫描。
5. 更新 API/界面/TDD 文档并完成最终规则审计。

### 里程碑 M4：发布候选

所有适用门禁 PASS；若浏览器依赖缺失导致 skip，状态是 NOT VERIFIED 而不是 PASS，不能结束 Phase 5。

### 门禁

- missing-assets 不再阻断应用导入。
- 新逻辑行/分支覆盖目标至少 80%。
- core、E2E、quality 使用明确 database mode 且退出码 0。
- runtime OpenAPI、源码、API index 和文档 METHOD/PATH 一致。
- diff/日志/fixture 中无真实知识或账号数据。
- 工作区无本任务产生的临时文件、端口和浏览器进程残留。

### 回退

- 测试夹具改动若影响生产静态行为立即回退，改为 runner 创建空 assets。
- 发布后可关闭 feature flag；应用回滚不删除 v3 表。
- 数据恢复只使用已验证 backup；文档批量删除不得作为应急回滚手段。

## 9. 发布序列

| 步骤 | 动作 | 继续条件 | 停止/回退条件 |
| --- | --- | --- | --- |
| 1 | 合并 schema/parser/API，feature off | temp/snapshot 集成全绿 | 迁移或隐私测试失败 |
| 2 | 部署候选并只读检查 OpenAPI/health | 路由/健康正常 | 静态挂载、认证或 schema 异常 |
| 3 | 开启测试环境 feature，执行合成 E2E | 用户旅程全绿 | 部分导入、错误 scope 或泄露 |
| 4 | 开启本地用户 feature | 备份已存在、回滚路径确认 | 409 无法恢复或旧来源误判 |
| 5 | 观察结构化 error/count 日志 | 无异常增长 | 关闭 feature，保留已导入 facts |

## 10. 风险与责任

| 风险 | Owner | 预防 | 二元检查 | 回滚 |
| --- | --- | --- | --- | --- |
| 私有正文进入模型/日志 | main-agent | 显式导入 + 独立 serializer | messages/log 扫描零命中 | 关闭 feature，回滚代码 |
| 文档导入部分成功 | main-agent | 单事务、先验证 | 失败前后行数/version 相同 | DB rollback/backup |
| 旧来源被伪造成文件 | main-agent | `manual/NULL` 迁移 | metadata-only fixture | 回滚投影，不删旧行 |
| scope 竞态误操作 | main-agent | sequence + mutation snapshot | 延迟响应 E2E | 关闭提交入口 |
| 删除损失手工条目 | main-agent | 默认 409、import lineage | 混合引用测试 | 事务 rollback/backup |
| 测试夹具修复掩盖部署问题 | main-agent | 优先 runner 建目录 | 生产缺 assets 仍可被部署检查发现 | 回退应用 mount 改动 |
| 解析器资源耗尽 | main-agent | bytes/section/count 限额 | 513 KiB/长段测试 | 请求拒绝，无写入 |
| 模型依据文案夸大 | main-agent | `provided_evidence` 术语 | UI 禁止承诺字符串 | 隐藏 evidence 面板 |
