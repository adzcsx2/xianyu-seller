# 架构设计

[返回 README](./README.md) · [上一篇：执行文档](./00-执行文档.md) · [下一篇：开发规范](./02-开发规范.md)

## 1. 设计结论

采用“文档原件 + 确定性章节 + 来源记录 + 显式导入事实 + 安全依据投影”的本地闭环。

关键选择：

- 文档是独立资源，不再用来源标题冒充文件。
- 上传只保存并解析，不能直接影响 AI；用户明确确认导入后，所选章节才成为现有 `facts`。
- 来源继续是审计关系，来源正文和备注不进入模型。
- 导入后的事实仍走现有知识运行时，不新建第二套检索或提示词管道。
- 系统记录哪些条目被提供给模型，并据此投影安全依据；不尝试证明模型内部真正采用了哪个来源。
- 普通用户只操作名称、正文、类型和开关，所有稳定 key、checksum、version 和关系 id 由服务端管理。

这既解决“看见 README 标题却不知道文件是否存在”的问题，也保留既有来源不泄露、轻量本地检索和全局知识库边界。

## 2. 当前链路与断点

```text
seed.source_refs 字符串 ──迁移──> ai_knowledge_sources
                                      │ source_ids
                    facts / rules / qa┘

管理 UI：title + reference + URL + notes
运行时：facts + qa + rules（刻意排除 sources）
```

当前链路能表达“某条知识声明来自一个引用记录”，但不能表达：

1. 是否真的上传过文件；
2. 文件校验和、编码、解析结果和章节；
3. 哪些章节被导入、哪些仍未生效；
4. 来源被哪些条目引用；
5. 本次问答实际把哪些已关联条目提供给模型。

标题类似文件名只是普通文本。现有 seed 迁移不会读取 `reference` 指向的路径，不能从显示名称推断文件存在。

## 3. 目标数据流

```text
浏览器选择 .md/.txt
        │ multipart + expected_version
        ▼
FastAPI 文档路由 ──流式限额──> KnowledgeDocumentParser
        │                              │
        │                        UTF-8 + 规范化 + 分段
        ▼                              ▼
ai_knowledge_documents ──1:N── ai_knowledge_document_sections
        │ 1:1 source                    │ 用户选择
        ▼                              ▼
ai_knowledge_sources <──source_ids── ai_knowledge_facts
        │                              │
        └──反向 usage 投影              ├── KnowledgeRuntimeService.match
                                       └── 单库 ask 上下文
                                                  │
                                provided_evidence │（独立安全投影）
                                                  ▼
                                            管理界面显示
```

上传、解析、导入、运行可用是四个不同事实。UI 必须显示状态，不以一个“来源引用”标题合并表达。

## 4. 文档生命周期

### 4.1 状态

| 状态 | 含义 | 是否进入 AI |
| --- | --- | --- |
| `metadata_only` | 只有旧来源记录，无文件实体 | 仅其已关联且启用的事实/问答可进入；来源本身不进入 |
| `parsed` | 文件已上传且解析成功，尚未导入章节 | 否 |
| `partially_imported` | 部分章节已导入为启用/停用事实 | 仅启用事实可能进入 |
| `imported` | 所有可导入章节已有 import 关系 | 仅启用事实可能进入 |

`runtime_enabled_count` 由关联条目当前 `enabled` 状态计算，不作为可漂移的缓存字段。

### 4.2 正常旅程

1. 用户打开一个全局知识库，进入“文档”。
2. 选择 UTF-8 Markdown/文本文件；前端先检查扩展名和明显大小，服务端重复验证。
3. 服务端读取最多 512 KiB + 1、规范化、计算 SHA-256、解析章节并事务保存文档、章节和一条 `source_kind=document` 来源。
4. UI 显示文件元数据和章节预览，并明确“尚未进入 AI”。
5. 用户选择章节并确认“导入为买家可见事实”。
6. 服务端在单事务内验证 version/限额/章节，创建 facts、source_ids 和 import rows，只将 base version 增加一次。
7. UI 回读知识库，显示导入/启用数量和反向关系。
8. 商品预览或知识库问答基于实际上下文条目返回安全的 `provided_evidence`。

### 4.3 失败与恢复

| 失败 | 服务端结果 | 用户恢复 |
| --- | --- | --- |
| 不支持扩展名/MIME | 415，无行写入 | 选择 `.md/.markdown/.txt` |
| 文件 >512 KiB | 413，无行写入 | 拆分文件 |
| 非 UTF-8/空文件 | 422，无行写入 | 转码或补充内容 |
| 重复 checksum | 200 返回已有文档，`duplicate=true`，version 不变 | 打开已有文档 |
| stale version | 409 `knowledge_version_conflict`，无部分写 | 保护草稿后重新加载 |
| 章节/内容总量超限 | 422，整批 rollback | 减少选择或清理旧条目 |
| 删除仍被使用 | 409 `knowledge_document_in_use`/`knowledge_source_in_use` | 查看关联，先处理或选择安全批量删除 |
| 上传请求被取消 | 服务端未提交则无行；已提交可按 checksum 幂等回读 | 重试相同文件 |
| 模型问答失败 | 502，不改变文档/知识 | 修复模型配置后重试 |

## 5. 数据模型

### 5.1 `ai_knowledge_documents`

| 字段 | 约束与语义 |
| --- | --- |
| `id` | UUID 主键 |
| `knowledge_base_id` | 所属全局知识库，删除 base 时清理 |
| `original_filename` | 浏览器提供的 basename，去除路径，1–180 字符 |
| `media_type` | 规范枚举 `text/markdown` 或 `text/plain` |
| `encoding` | 首版固定 `utf-8` |
| `byte_size` | 原始上传 bytes 大小，1..524288 |
| `content_sha256` | 原始 bytes SHA-256；`UNIQUE(knowledge_base_id, content_sha256)` |
| `parser_version` | 首版 `text-sections-v1` |
| `parse_status` | `parsed`；失败默认不建行 |
| `created_at/updated_at` | 审计时间 |

原始客户端路径和完整原始文件 blob 永不保存。解析器可在请求内持有规范化正文，但持久层只保存解析成功的章节；列表 DTO 不返回章节正文。

### 5.2 `ai_knowledge_document_sections`

| 字段 | 约束与语义 |
| --- | --- |
| `id` | UUID 主键 |
| `document_id` | 所属文档 |
| `ordinal` | 从 1 开始，文档内唯一 |
| `heading_path` | 规范化标题层级展示文本 |
| `anchor` | 服务端生成稳定锚点，不依赖浏览器 slug 实现 |
| `content` | 私有章节正文；每个导入片段 1–800 字符 |
| `content_sha256` | 规范化章节摘要，用于重试/差异 |

Markdown 标题下的长内容按空行和句子边界确定性拆分，保证每片段适配现有 fact 800 字限制。纯文本没有标题时以文件名作为展示标题、按段落拆分。

### 5.3 `ai_knowledge_document_imports`

| 字段 | 约束与语义 |
| --- | --- |
| `document_id/section_id` | 来源章节 |
| `target_kind` | 首版固定 `facts` |
| `target_id` | 自动创建的 fact id |
| `imported_content_sha256` | 导入时章节摘要 |
| `created_at` | 导入审计时间 |

主键/唯一约束防止同一章节重复导入。未来支持其他 target kind 需要新需求，本计划不预埋自动规则/QA 生成。

### 5.4 `ai_knowledge_sources` 扩展

- 新增 `source_kind`：`manual` 或 `document`，默认 `manual`。
- 新增可空且唯一的 `document_id`；document 类型必须指向同库文档，manual 必须为空。该字段是 document/source 一对一关系的唯一所有者，document 表不反向保存 `source_id`。
- 旧行迁移为 `manual/NULL`，即使标题或 reference 像文件名也不推断。
- document source 的 `title` 默认用安全 basename，`reference` 可用章节/上传说明，但 notes 和 URL 不自动生成。

### 5.5 聚合版本

- 新建文档连同 sections/source 是一次 mutation，成功后 base version +1。
- 导入任意多个章节是一次 mutation，成功后 version +1。
- 删除文档/自动导入条目是一次 mutation，成功后 version +1。
- 只读 usage、文档详情、解析预览不修改 version。
- 重复 checksum 返回已有行，version 不变。

## 6. 解析合同

### 6.1 接受规则

- 扩展名：`.md`、`.markdown`、`.txt`，大小写不敏感。
- 编码：UTF-8 或 UTF-8 BOM；NUL byte、解码错误、全空白拒绝。
- 大小：原始 bytes 不超过 512 KiB。
- 内容：统一 CRLF/CR 为 LF，Unicode NFKC 仅用于 key/checksum 比较；展示正文不做破坏性字符替换。
- Markdown：识别 ATX 标题（`#` 到 `######`）；代码块内的 `#` 不作为标题。
- 分段：保持顺序和标题路径；片段最多 800 字；不截断 UTF-8 code point，不产生全空片段。

### 6.2 安全规则

- parser 输入是 bytes 和 basename，不接收文件系统路径。
- 不解析 HTML、不执行 Markdown、不跟随链接、不读取图片、不加载 include。
- 不调用模型、HTTP、shell、浏览器或第三方转换器。
- 上传文件正文只进忽略的运行数据库或临时测试 DB；日志只记录 document id、bytes、section count、checksum 前缀和 error_code。

## 7. API 合同

所有端点沿用 `get_current_user`。全局库只要求登录；商品 preview 仍先验证 cookie 和 item scope。写操作受 `feature_knowledge_base_enabled` 控制。

### 7.1 文档端点

| Method | Path | 输入 | 主要输出/副作用 |
| --- | --- | --- | --- |
| GET | `/knowledge-bases/{base_id}/documents` | 无 | 元数据、状态、section/import/usage 计数；无正文 |
| POST | `/knowledge-bases/{base_id}/documents` | multipart `file`, `expected_version` | 保存文档、sections、source；重复 checksum 幂等返回 |
| GET | `/knowledge-bases/{base_id}/documents/{document_id}` | 无 | 显式章节预览，返回解析章节正文；列表端点不返回正文 |
| POST | `/knowledge-bases/{base_id}/documents/{document_id}/imports` | JSON `expected_version`, `section_ids` | 原子创建 facts/source 关系/imports |
| DELETE | `/knowledge-bases/{base_id}/documents/{document_id}` | query `expected_version`, `delete_imported=false` | 默认无使用才删；显式安全批量删除自动导入事实 |

上传成功新建使用 201；重复内容使用 200，并返回：

```json
{
  "document": {"id": "...", "status": "parsed", "section_count": 3},
  "duplicate": false,
  "version": 4
}
```

示例省略文件名、正文和来源内容，避免把业务知识写入计划。

### 7.2 来源反向关系

来源摘要至少包含：

```json
{
  "source_kind": "document",
  "document_status": "partially_imported",
  "linked_entry_count": 2,
  "runtime_enabled_count": 1,
  "usage": [
    {"kind": "fact", "content_id": "...", "label": "章节标题", "enabled": true}
  ]
}
```

`usage` 可以放在按需详情 endpoint，若列表只返回计数；最终实现选择一种后必须在 OpenAPI、types 和测试中统一。`label` 是管理标题，不是正文。

### 7.3 分型错误

所有知识业务错误使用统一 detail：

```json
{
  "error_code": "knowledge_document_in_use",
  "message": "文档仍有关联条目",
  "usage": {"linked_entry_count": 2, "runtime_enabled_count": 1}
}
```

稳定 error code：

- `knowledge_version_conflict`
- `knowledge_key_conflict`
- `knowledge_document_in_use`
- `knowledge_source_in_use`
- `knowledge_validation_error`

HTTP 413/415 也返回稳定 code。服务端异常正文、完整 checksum、路径和内容不回显。

### 7.4 自动 key

公共创建请求不再接受 `fact_key/source_key/rule_key/qa_key`。服务端按内容类型生成不可猜业务含义的稳定前缀 + 随机/摘要片段；更新请求禁止改 key。

seed/migration 使用独立内部方法保留明确 key，不能通过公共 `KnowledgeMutationRequest` 绕过。

## 8. 运行时和依据证据

### 8.1 不改变的模型边界

- `KnowledgeRuntimeService.snapshot` 继续只向运行逻辑暴露事实、问答和规则需要的字段。
- `build_context` 继续只拼接买家可见 fact/answer。
- `_knowledge_base_qa_prompt` 继续排除 sources、notes、文档正文和本地元数据。
- 文档没有导入为 fact 前，任何内容不得进入自动回复或知识库问答。

### 8.2 依据计算

依据计算与 prompt 构建共享同一个“已选择内容 id 集合”，但输出走独立 serializer：

```text
selected content ids ─┬─> context/prompt builder（只取 buyer-visible 内容）
                      └─> evidence resolver（只取 source title + section + type）
```

这样既能证明某个来源关联的内容被提供给模型，又不会把 source 元数据混进 prompt。

商品 preview 已有 match 集合，依据只解析这些 match。单库 ask 当前会提供所有启用事实/问答/规则，因此依据对应实际纳入预算后的记录；若字符预算淘汰记录，依据也必须同步淘汰。

响应字段名为 `provided_evidence`，UI 文案为“本次提供给 AI 的依据”。固定回复未调用模型时返回空依据并标记 `model_called=false`（如现有 response 无此字段则本次扩展）。

## 9. 前端状态机

```text
idle
 └─ select file → validating → uploading
                             ├─ error（保留文件，可重试/取消）
                             └─ parsed → selecting sections → importing
                                                              ├─ conflict（保护选择，刷新）
                                                              ├─ error（无部分导入）
                                                              └─ imported → reload detail
```

UI 信息层级：

1. “文档”tab 管上传和解析；
2. “来源引用”tab 管手工来源和反向关系；
3. facts/rules/QA 表单只选择来源，不上传文件；可提供跳转到文档 tab；
4. 内部 key 仅在高级信息只读展示；
5. 保存前显示字段级错误，顶部 toast 只用于全局结果。

账号/商品绑定请求使用 scope token：请求开始捕获 `{cookieId,itemId,sequence}`，只有与当前选择和最新 sequence 都相等时才更新 state。mutation 同样捕获 scope，提交中禁止切换或在返回时校验并丢弃旧结果。

## 10. 删除与清理

- 手工来源无引用时可直接删除；有引用返回 source in-use。
- 文档无 imports/手工引用时可删除 document、sections 和自动 source。
- 文档只有自动导入事实时，用户可显式选择“删除文档及自动导入条目”；单事务删除 import facts、source、sections、document。
- 若 source 还被手工创建/编辑的 fact、rule、QA 引用，即使 `delete_imported=true` 也返回 409；UI 展示关联并要求逐项处理。
- 删除全局知识库继续清理全部文档表和 bindings；返回的影响计数增加 document count，但不回显内容。
- E2E 和 temp 测试必须关闭浏览器、HTTP server、临时 DB；运行日志/构建产物只放 `logs/`。

## 11. 迁移与兼容

1. 用 `CREATE TABLE IF NOT EXISTS` 和列存在检查前向增加表/字段。
2. 所有既有 source 设置 `source_kind=manual`、`document_id=NULL`。
3. 不读取 reference、不探测文件存在、不从标题构造文档。
4. `get_knowledge_base` 增加 documents/usage 字段时保留旧 facts/sources/rules/qa 字段。
5. 旧前端忽略新增字段仍可读；旧写接口不因本轮复活。
6. 新前端遇到缺少新增字段时按 `metadata_only/0` 安全展示，便于滚动发布。
7. migration marker 与 DDL/必要数据修正同事务；重复启动 no-op。

## 12. 可观测性与回滚

允许日志：operation、base/document/content id、version、byte/section/count、checksum 短前缀、error code、duration。禁止日志：文件名中的敏感路径、正文、notes、答案、规则、买家问题、账号配置。

回滚顺序：

1. 功能异常时关闭知识库 feature flag，写路径立即停止；现有自动回复仍只读取已导入 facts。
2. 应用代码可回滚到前版本；新增表/列保留，旧代码忽略。
3. 若本地运行数据需要恢复，只使用执行前由测试 runner/运维流程创建的 SQLite backup；不写手工逆向 DELETE。
4. 不把订单硬安全或秘密保护作为回滚项关闭。

## 13. 未选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 把文件正文直接塞进 source.notes | 不采用 | notes 既不入模也不适合版本、分段和大小管理 |
| 上传后立即把全文给模型 | 不采用 | 无人工公开确认、不可解释、容易泄露私有内容 |
| 自动用 LLM 抽取 facts/QA/rules | 不采用 | 需外发私有文档且结果不确定，超出当前授权 |
| 运行时直接检索 document sections | 不采用 | 会形成第二套知识模型并绕过现有事实审批边界 |
| 根据 `README.md：产品简介` 猜本地文件 | 不采用 | 标题不是路径，服务器也不应任意读文件 |
| 只在前端扫描 source_ids 算 usage | 不采用 | 容易漂移、权限与分页不完整，后端应给一致读模型 |
| 所有 409 都提示刷新 | 不采用 | 引用占用和重复内容不是刷新可解决的问题 |
| 首版加入 PDF/DOCX/OCR | 不采用 | 需要新解析依赖、安全审计和更复杂失败恢复 |

## 14. 关键决策摘要

| 决策 | 选择 |
| --- | --- |
| 文档格式 | UTF-8 Markdown/纯文本，512 KiB |
| 解析 | 纯 Python、确定性、无网络/AI |
| 生效方式 | 用户选择章节后原子导入 facts |
| 来源关系 | document 自动 source + 现有 source_ids + imports lineage |
| AI 证据 | 与实际上下文选择同步的 `provided_evidence` |
| 用户键 | 公共 CRUD 全部服务端生成，编辑时不可变 |
| 并发 | 聚合 version + 前端 scope sequence |
| 删除 | 默认拒绝占用；显式且原子的安全批量删除 |
| 兼容 | 旧来源一律 metadata-only，不伪造文档 |
