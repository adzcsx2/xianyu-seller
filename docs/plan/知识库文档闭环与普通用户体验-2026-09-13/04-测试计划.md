# 测试计划

[返回 README](./README.md) · [上一篇：修复路线图](./03-修复路线图.md) · [下一篇：测试用例清单](./05-测试用例清单.md)

## 1. 测试目标

证明知识库文档能力对普通用户是完整、真实且可恢复的：文件状态不能靠标题猜测，上传不等于生效，导入必须原子，来源关系可反查，提供给 AI 的依据可核对，私有正文不越界，异步竞态不能操作错误 scope。

## 2. 测试环境

| 环境 | 用途 | 数据策略 | 禁止事项 |
| --- | --- | --- | --- |
| Python 单元 | parser、分段、校验、错误映射 | 内存 bytes、合成文本 | 不读本地业务文件、不联网 |
| temp SQLite | schema、迁移、事务、回滚 | 空白临时 DB、合成 v2 fixture | 不连接 live DB |
| snapshot SQLite | core/集成回归 | runner 创建一致快照 | 不写原数据库 |
| FastAPI TestClient | auth、multipart、OpenAPI、错误 | 注入临时 DB、合成用户 | 不使用真实账号/模型 |
| 模型单测 | prompt/evidence 隔离 | mock 既有客户端 seam | 不调用外部模型 |
| Python Playwright | 普通用户浏览器旅程 | 随机端口、临时 DB、合成文件 | 不复用 8080、不依赖桌面控制 |
| detached frontend build | 类型与生产打包 | `logs/test-artifacts/` | 不覆盖提交的 `static/` |

## 3. 测试数据规范

- 文件内容使用明显合成的英文/中文占位段落，不复制运行知识库、seed 或真实 README。
- 账号、cookie、商品和知识库 id 使用 `test-*`、UUID 或 fixture 生成值。
- 文件名覆盖正常、同名不同内容、路径伪装、Unicode 和控制字符，但不使用真实用户路径。
- source notes 使用 `synthetic-private-note`，用于断言不进入 prompt/response/log。
- 模型响应固定为合成文本；任何真实 API Key、模型请求或买家消息均不允许。

## 4. 分层策略

### 4.1 Parser 单元测试

目标模块：拟新增 `app/knowledge_documents.py`。

覆盖：

- `.md/.markdown/.txt`、大小写 suffix、UTF-8 BOM、CRLF。
- Markdown 标题层级、无标题正文、代码块内 `#`、空标题、连续标题。
- 纯文本段落、超 800 字分段、Unicode 边界、空白规范化。
- 空文件、非法 UTF-8、NUL、错误扩展名、513 KiB、伪装 MIME。
- 同输入稳定 section ordinal/anchor/checksum；不同内容 checksum 不同。
- 解析器不能访问路径、网络、数据库或 AI。

成功标准：所有有效输入得到非空、顺序稳定且每片段 1–800 字；所有无效输入抛出可映射异常且无副作用。

### 4.2 SQLite/领域集成

目标：`DBManager` 新 schema、CRUD、usage、import、delete、migration。

覆盖：

- v3 DDL 重复初始化、从 v2 fixture 前向迁移、旧 source 的 metadata-only 投影。
- document/source 一对一、section/import 外键语义、base 显式清理。
- 上传成功/重复 checksum、同名不同内容、跨库 document/source/section 拒绝。
- 多章节导入只 bump version 一次；自动 facts 和 source_ids/imports 同时存在。
- stale version、超限、重复 section、注入中途异常全部 rollback。
- 默认删除占用 409；显式批量只删自动导入 facts；混合手工引用继续拒绝。

成功标准：每个 mutation 都有前后行数/version 断言；失败状态与调用前完全一致。

### 4.3 API 合同

目标：FastAPI models/routes/error mapper/OpenAPI。

覆盖：

- 登录和 feature flag；base/document 404；非法 base/document/section scope。
- multipart 正常、空文件、413、415、422、重复、取消/断连可重试。
- 导入 request 的 strict int/list/extra/唯一/数量限制。
- 四类内容 create 不需要 key，客户端提交 key/更新 key 被拒。
- error code 稳定且与 status 对应，message 不用于程序分支。
- list/detail/usage/evidence DTO 不回显正文、notes、路径和内部规则。
- OpenAPI 中存在五个文档 operations 且 schema 不暴露 `_kind`。

成功标准：所有状态码、error_code、response shape 和副作用均与架构合同一致。

### 4.4 运行时与 AI 隔离

目标：`KnowledgeRuntimeService`、`AIReplyEngine`、ask/preview response。

覆盖：

- parsed 但未导入的 document 不改变 snapshot、match、prompt。
- 导入但 disabled 的 fact 不进入上下文；enabled 后按现有检索进入。
- source title/reference/notes/document content/source id 不出现在模型 messages。
- evidence 只来自实际纳入字符预算的 content refs；被预算淘汰的条目无 evidence。
- preview 只为 matches 返回 evidence；ask 为实际 prompt records 返回 evidence。
- 固定回复未调用模型且 evidence 为空；模型失败不改变知识数据。

成功标准：可以双向比对 `content_refs ↔ provided_evidence`，且敏感 marker 在 messages/response/log 中零命中。

### 4.5 React/TypeScript 合同

覆盖：

- `KnowledgeDocument`、`KnowledgeSourceUsage`、`KnowledgeProvidedEvidence` 类型。
- API helper 使用 `FormData`，不手工设置错误 multipart boundary。
- 文档 tab、限制文案、状态标签、章节选择、买家可见确认。
- 创建 facts/sources/rules/QA 请求不含 key。
- 保存按钮 valid/dirty/submitting 逻辑；字段错误可见。
- `error_code` 分型；source/document in-use 不显示版本冲突。
- request sequence/abort 和 mutation scope snapshot。

静态源码断言只作补充，不能替代下述浏览器行为。

### 4.6 无头 E2E

新增 `tests/test_knowledge_base_ui.py` 并注册 `E2E_TEST_MODULES`。

主旅程：

1. 登录合成用户，打开知识库。
2. 打开合成库的文档 tab。
3. 上传内存 Markdown；观察“已解析、尚未进入 AI”。
4. 选择章节，确认买家可见并导入。
5. 来源/文档显示关联与运行启用计数。
6. 发起知识库问答，显示回答与“本次提供给 AI 的依据”。
7. 刷新页面，状态保持。

异常旅程：旧来源 metadata-only、重复上传、非法格式、占用删除、版本冲突、快速账号/商品切换、取消未保存草稿。

成功标准：语义定位器全部通过，控制台无 error，测试未 skip，结束后浏览器/server/temp DB 清理。

### 4.7 迁移、恢复与发布

- 空 DB → v3。
- v2 → v3，旧来源行数/id/key 不变且全部 metadata-only。
- v3 初始化两次 no-op。
- 迁移异常时 marker/schema 数据一致；修复后可重试。
- backup restore 后文档/facts/imports/version 一致。
- 旧前端读取新增字段时不崩溃；新前端面对旧 response 缺字段时安全默认。
- feature off 后新写操作拒绝，现有读取/自动回复不被破坏。

## 5. 当前基线与先决修复

已知基线：知识库相关四组定向测试共 96 项通过。完整 `core + snapshot` 曾运行 435 项并出现 39 个同源错误：test runner 指向的 `frontend-static` 缺少 `assets`，导致 `StaticFiles` 在应用导入时失败。这不是知识业务断言失败，但使完整门禁无效。

执行顺序：

1. 用 `tests/test_automation_framework.py` 复现测试静态目录缺口。
2. 优先让 runner 在应用导入前创建 `frontend-static/assets`。
3. 保留生产候选缺失 assets 的可见失败；不得用全局 `check_dir=False` 掩盖部署错误。
4. 重跑 core，确认同源错误消失后再评价知识功能回归。

## 6. RED/GREEN 命令

从仓库根目录执行；目标文件新增前 RED 可因模块/endpoint 缺失失败，GREEN 后命令必须 exit 0。

```powershell
python -m unittest tests.test_knowledge_documents -v
python -m unittest tests.test_global_knowledge_contract -v
python -m unittest tests.test_global_runtime_contract -v
python -m unittest tests.test_ai_reply -v
python -m unittest tests.test_product_knowledge -v
python -m unittest tests.test_automation_framework -v
```

全量门禁：

```powershell
python scripts/run_tests.py --list
python scripts/run_tests.py --suite core --database snapshot
python scripts/run_tests.py --suite e2e --database snapshot
python scripts/run_tests.py --quality --database snapshot
```

前端检查由 `--quality` 调用本地 TypeScript 与 detached build；不另行宣称仓库不存在的 ESLint/Ruff 结果。

## 7. 覆盖率策略

- 新 parser 模块：行与分支目标 ≥90%，所有拒绝分支必须覆盖。
- 新 DB/API 逻辑：新增或实质修改可测试代码行与分支目标 ≥80%。
- 认证、version、导入 rollback、删除保护、私有字段隔离和 scope race 是关键分支，必须显式测试，不能只依赖百分比。
- legacy 大文件整体覆盖率不是本改动通过条件；报告 changed-module/changed-branch 证据和完整回归结果。
- 无 coverage 工具或报告失败时标记 NOT VERIFIED，不能用测试数量替代覆盖率结论。

## 10. 回归范围

除新文档能力外，至少覆盖：

- 全局知识库 CRUD、四类内容 CRUD、聚合 version。
- 商品绑定/解绑、重复绑定和空商品。
- Passistant seed/migration marker、旧前端知识 GET 兼容。
- 来源不入模、内部规则、价格/议价、安全固定回复、普通商品零污染。
- 知识库 ask 的账号配置隔离、错误清理和长回答。
- feature flags、认证、商品 scope。
- SPA no-cache、前端生产构建和随机端口 E2E。

## 11. 缺陷处理

- 新测试暴露的范围内缺陷：记录 RED，最小修复，重跑同一测试后再扩回归。
- 既有无关失败：必须先在改动前基线复现并记录；不能删除/skip 测试或修改业务语义掩盖。
- 同一 missing-assets 根因的多个 error 作为一个基础设施缺陷处理，但修复后必须重跑完整 core。
- 私有数据疑似泄露：立即停止，删除未提交泄露 artifact（精确确认路径后）、轮换外部凭据由用户决定，并记录 blocker；不得继续发布。

## 12. 证据保存

执行日志只记录命令、时间、数据库模式、测试数、PASS/FAIL、覆盖率摘要和脱敏错误类型。详细 runner artifact 留在 `logs/test-artifacts/<run-id>/`，不复制到文档或提交。
