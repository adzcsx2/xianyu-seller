# 开发规范

[返回 README](./README.md) · [上一篇：架构设计](./01-架构设计.md) · [下一篇：修复路线图](./03-修复路线图.md)

## 1. 适用范围

本规范约束本计划涉及的 Python/FastAPI/SQLite、React/TypeScript、自动化测试和文档变更。它是实现指导，不授权修改与知识库文档闭环无关的代码。

## 2. 必须遵守

- 先测试后实现：每个行为先得到有效 RED，再做最小 GREEN。
- 先查 API index，再核对源码；index stale 时记录并从源码重建，不能把索引当权限事实。
- 所有文档 bytes、解析、持久化和引用业务放在服务/DB 边界，不在 React 或 FastAPI route 中复制核心算法。
- 新解析逻辑放入拟新增的 `app/knowledge_documents.py`，保持无网络、无数据库、无模型依赖，便于纯单元测试。
- SQLite mutation 必须在 `DBManager` 的锁与单事务内完成，所有验证先于第一条写 SQL。
- 复用知识库聚合 version；一次用户动作最多递增一次。
- API request/response 使用明确 Pydantic 模型，`extra="forbid"`；不得继续用允许任意字段的宽松 request 表达新文档能力。
- 所有公开创建请求由服务端生成 key，更新请求不接受 key。
- 前端通过 `frontend/services/api.ts` 和既有 request 封装访问业务 API；组件不直接散落 `fetch`。
- 前端以业务中文描述字段与错误；内部 id/key/version 只在必要时只读显示。
- 所有正文和错误详情按纯文本渲染；禁止 `dangerouslySetInnerHTML`。
- 测试只用合成文档、账号、商品和模型响应；任何真实知识正文和账号数据不得进入 fixture 或 snapshot。
- 所有测试/构建日志只能位于仓库 `logs/` 下。

## 3. 明确禁止

- 禁止根据 `source.reference`、`source.title` 或 URL 去读本地文件或网络资源。
- 禁止运行 Markdown、HTML、代码块、链接、include、脚本、宏或模板。
- 禁止上传即生效、解析即生效或在用户确认前创建启用事实。
- 禁止把原始文档、source notes/reference、内部规则正文或 source id 放入模型消息。
- 禁止在日志打印文件正文、完整 checksum、原始路径、回答、买家问题、token 或账号配置。
- 禁止用文件名作为唯一标识；同名文件允许，内容去重以 base + SHA-256 为准。
- 禁止静默解除引用、级联删除手工条目或用 last-write-wins 绕过 version。
- 禁止将 duplicate、in-use、validation 全部映射为 version conflict。
- 禁止在组件加载中不校验 scope 就执行 `setBindings`。
- 禁止新增向量/embedding/文档解析依赖；若确有需要，停止本计划并提出独立依赖评审。
- 禁止直接写 live DB 做迁移失败、删除或回滚测试。
- 禁止借机重构 `app/reply_server.py`、`app/db_manager.py` 或用户已有改动的无关部分。

## 5. 文档解析合同

### 5.1 常量

建议在 `app/knowledge_documents.py` 集中定义并由 API/测试复用：

```python
SUPPORTED_SUFFIXES = {".md", ".markdown", ".txt"}
MAX_DOCUMENT_BYTES = 512 * 1024
MAX_SECTION_CHARACTERS = 800
PARSER_VERSION = "text-sections-v1"
```

这些常量不得由前端单独复制为不同值；前端可用于早期提示，服务端常量是事实源。

### 5.2 纯函数接口

```python
@dataclass(frozen=True)
class ParsedSection:
    ordinal: int
    heading_path: str
    anchor: str
    content: str
    content_sha256: str

@dataclass(frozen=True)
class ParsedDocument:
    original_filename: str
    media_type: str
    byte_size: int
    content_sha256: str
    normalized_content: str
    parser_version: str
    sections: tuple[ParsedSection, ...]

class KnowledgeDocumentParser:
    def parse_bytes(self, filename: str, content: bytes) -> ParsedDocument: ...
```

纯函数只能从参数读取内容。抛出领域级 validation 异常或 `ValueError`，由 route 统一映射；不能返回半解析对象。

### 5.3 文件名

- 使用 `PurePath(filename.replace("\\", "/")).name` 取得 basename。
- 去除控制字符和首尾空白，长度 1–180。
- 文件名只用于展示和 suffix 判断，不参与文件系统访问。
- 不把浏览器伪造的 MIME 作为唯一依据；suffix、MIME 与解码结果共同校验。

### 5.4 Markdown 分段

- 用小型状态机识别 fenced code block；代码块内 `#` 不建标题。
- 标题栈按级别维护，`heading_path` 使用 `父 / 子`。
- 标题前正文归入文档默认章节。
- 先按空行拆 paragraph；超 800 字的 paragraph 再按中文/英文句末和硬上限拆分。
- 每个 section content 1–800 字，顺序稳定；anchor 由 ordinal + 标题摘要生成，不依赖随机数。

不得用一个复杂正则一次解析整个 Markdown，也不得尝试成为完整 Markdown renderer。

## 6. SQLite 与事务模板

### 6.1 验证顺序

一次导入必须遵循：

1. 在锁内读取 base 并比较 `expected_version`；
2. 读取 document/sections 并验证同库；
3. 验证 section ids 唯一、存在、未导入；
4. 计算新增 fact 数和聚合总数是否超限；
5. 生成所有 ids/keys 和待写 rows；
6. 执行 INSERT；
7. bump base version 一次；
8. commit；
9. commit 后构造安全 DTO。

任何异常都 `rollback` 后原样映射领域错误。不要在事务中调用外部服务。

### 6.2 自动 key

公共创建使用服务端生成：

```text
fact-<随机或摘要 12 字符>
source-<随机或摘要 12 字符>
rule-<随机或摘要 12 字符>
qa-<随机或摘要 12 字符>
```

文档章节导入可使用 `doc-<document checksum prefix>-<ordinal>`，冲突时追加确定性短后缀。key 只满足现有 `[a-z0-9._-]` 约束，不包含文件标题或私有业务词。

seed/migration 显式 key 走私有方法参数，例如 `allow_explicit_key=True`，不能暴露到 HTTP。

### 6.3 引用完整性

- `source.document_id` 是唯一关系所有者，必须与 source 同库且唯一；document 不保存反向 `source_id`。
- import 的 section 必须属于 document；target fact 必须属于同一 knowledge base。
- 删除前统一调用 usage 查询，不在三个调用点重复写不同扫描逻辑。
- 不依赖 SQLite foreign key 一定开启；base/document 删除保留显式清理和测试。

## 7. API 规范

### 7.1 上传读取

使用 `UploadFile` 分块读取，累计超过上限立即停止：

```python
chunks: list[bytes] = []
total = 0
while True:
    chunk = await file.read(64 * 1024)
    if not chunk:
        break
    total += len(chunk)
    if total > MAX_DOCUMENT_BYTES:
        raise KnowledgeDocumentTooLarge(...)
    chunks.append(chunk)
```

在 `finally` 关闭上传对象。不得先无界 `await file.read()` 再检查大小。

### 7.2 严格请求

- 导入 JSON：`expected_version: StrictInt >= 1`、`section_ids: list[str]`，1..100、唯一。
- 删除 query：`expected_version >=1`、`delete_imported: StrictBool=false`。
- 公共内容创建为 kind-specific Pydantic model；创建不含 key，更新也不含 key。
- 所有 extra 字段拒绝；不得继续依赖 `_kind` 或 `extra="allow"`。

### 7.3 错误映射

前端只依赖 `error_code`，HTTP status 仍保留通用语义：

| status | error_code | UI 动作 |
| --- | --- | --- |
| 409 | `knowledge_version_conflict` | 保护草稿并重新加载 |
| 409 | `knowledge_key_conflict` | 提示重复，保持表单 |
| 200 | `duplicate=true` | 打开已有文档，version 不变 |
| 409 | `knowledge_source_in_use` | 展开关联条目 |
| 409 | `knowledge_document_in_use` | 展开影响并给安全删除选择 |
| 413 | `knowledge_document_too_large` | 显示 512 KiB 限制 |
| 415 | `knowledge_document_type_unsupported` | 显示支持格式 |
| 422 | `knowledge_validation_error` | 映射到字段或通用校验区 |

message 可改善可读性，但不能作为程序分支条件。

## 8. 安全依据规范

### 8.1 选择结果

上下文选择函数应返回：

```python
ContextSelection(
    text="...",              # 真正发给模型的 buyer-visible 内容
    content_refs=(...),       # 仅内部用于 evidence resolver
)
```

`content_refs` 包含 base id、kind、content id；不能包含 source notes、正文或路径。evidence resolver 在模型调用之外查询来源安全摘要。

### 8.2 DTO

```typescript
interface KnowledgeProvidedEvidence {
  source_id: string;
  title: string;
  source_kind: 'manual' | 'document';
  document_id?: string | null;
  section?: string | null;
  content_kind: 'fact' | 'qa' | 'rule';
  content_id: string;
}
```

若内部 rule 进入单库问答，可返回其来源标题和类型，但不能返回 rule name/config/instruction。商品固定回复没有模型调用时依据为空。

### 8.3 文案

唯一推荐标题：`本次提供给 AI 的依据`。

禁止：`AI 已引用`、`回答来自`、`模型确认使用`。模型生成是非确定性的，系统只能证明上下文提供行为。

## 9. React 状态规范

### 9.1 scope request

```typescript
const bindingsRequestSeq = useRef(0);

const loadBindings = async (cookieId: string, itemId: string) => {
  const seq = ++bindingsRequestSeq.current;
  const result = await getKnowledgeBindings(cookieId, itemId);
  if (seq !== bindingsRequestSeq.current) return;
  if (cookieId !== selectedAccountRef.current || itemId !== selectedItemRef.current) return;
  setBindings(result);
};
```

实际实现可用 AbortController，但必须与现有 request 封装兼容；不能只捕获 React render 时的闭包值。

### 9.2 表单状态

每个 draft 维护：`values`、`touched`、`errors`、`dirty`、`submitting`。规则：

- 初次打开不显示全屏错误；blur 或提交后显示字段错误。
- 保存按钮要求 `dirty && valid && !submitting`。
- tab/关闭/刷新/scope 切换沿用已有未保存确认。
- 服务端 422 保留 draft；成功回读后才清 dirty。
- document selection 在 version conflict 后保留，待用户确认刷新。

### 9.3 可访问性

- file input 有明确 label、accept 和限制说明。
- 状态使用 `role="status"`，错误使用 `role="alert"`。
- modal 有 title、Escape、焦点可达和提交中防关闭策略。
- 不能只用颜色表达已上传/未导入/已导入。

## 10. 测试模板与约束

### 10.1 合成文档

```python
SYNTHETIC_MARKDOWN = b"# Example\n\nPublic synthetic paragraph.\n"
```

测试内容必须明显虚构，不复制 seed、运行 DB 或真实 README 内容。

### 10.2 事务断言

失败前后至少比较：base version、document/source/fact/section/import 行数、引用 JSON。不能只断言抛错。

### 10.3 模型隔离

mock 在 `AIReplyEngine` 调用客户端的既有 seam；断言 messages 不含 synthetic source notes/path，并核对 evidence 与实际选中 content ids。不要通过修改生产行为让 mock 更容易断言。

### 10.4 E2E

- 通过 Python Playwright、随机端口、临时/快照 DB。
- 用 `set_input_files` 的内存 payload 或测试临时文件；临时文件放 runner artifact 目录。
- 用语义定位器，不依赖 Tailwind class 或构建 hash。
- 等待响应/可见状态，不使用任意 sleep。
- 测试结束关闭 page/browser/server，并验证无残留 mutation 到 live DB。

## 11. 反模式

| 反模式 | 风险 | 替代 |
| --- | --- | --- |
| 来源标题含 `.md` 就当已上传 | 伪证据 | 只看 document_id/source_kind |
| 上传后自动启用全文 | 私有内容泄露 | 预览 + 显式章节导入 |
| 文档正文塞进问答 prompt | 绕过事实审批 | 只导入 facts |
| 前端生成业务 key | 用户负担、冲突 | 服务端生成且更新不可变 |
| 409 全部刷新 | 无法解决 in-use/duplicate | error_code 分型 |
| 并发请求最后返回者覆盖 | scope 错乱 | sequence/abort + scope snapshot |
| 文档删除级联所有引用 | 数据丢失 | 默认拒绝 + 仅自动导入范围的显式事务 |
| 用静态字符串测试代替用户旅程 | 假绿 | API 集成 + Playwright E2E |
| 修复测试夹具时放宽生产静态挂载 | 掩盖部署错误 | 优先在 runner 创建 assets |

## 12. 代码审查清单

- [ ] 所有文件读取都有 512 KiB 上限且在累计时执行。
- [ ] parser 不接受路径、不联网、不调用模型。
- [ ] 上传/导入/删除每个动作只 bump version 一次。
- [ ] 所有写失败前后表计数与 version 不变。
- [ ] 旧 source 不被推断为 document。
- [ ] 四类公共创建请求不含 key，更新不能改 key。
- [ ] evidence 与实际上下文选择共源，source 元数据不进 prompt。
- [ ] 409 分型，UI 有可行动恢复。
- [ ] 绑定请求具备 stale response 防护。
- [ ] 测试和文档没有真实知识/账号数据。
- [ ] target、core、E2E、quality 结果按规范记录。
