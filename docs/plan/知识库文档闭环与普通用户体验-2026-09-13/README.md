# 知识库文档闭环与普通用户体验

[执行文档](./00-执行文档.md) · [架构设计](./01-架构设计.md) · [开发规范](./02-开发规范.md) · [修复路线图](./03-修复路线图.md) · [测试计划](./04-测试计划.md) · [测试用例清单](./05-测试用例清单.md)

## 1. 背景

当前知识库已经具备全局知识库、商品绑定、事实、来源、规则、公开问答和知识库问答，但“来源引用”只是人工填写的元数据。界面显示类似 `README.md：产品简介` 的标题，并不能证明文件已上传、内容已解析或回答时使用了它。

普通用户目前会遇到四个断点：

- “来源引用”没有文件上传、解析预览、导入状态或文档删除入口。
- 新增事实、来源和规则要求填写技术内部键，且保存前缺少足够的表单校验。
- 来源列表没有反向显示被哪些事实、规则或问答引用；被引用来源删除失败时，前端还把 409 误报为版本变化。
- 快速切换账号或商品时，较早返回的绑定请求可能覆盖当前选择，造成显示与操作对象不一致。

本计划把文档能力做成一条可观察、可回滚的本地闭环：

```text
上传文档 → 本地校验与解析 → 预览章节 → 明确导入为买家可见事实
         → 自动建立来源关系 → 显示反向引用 → 预览/问答显示“提供给 AI 的依据”
```

## 2. 目标

1. 普通用户可以在知识库编辑器中上传 UTF-8 Markdown 或纯文本文件，不需要手填路径、URL 或内部键。
2. 上传不等于立即生效；用户先看解析预览，再明确确认哪些章节导入为买家可见事实。
3. 文档、来源、导入条目和运行时证据之间可追踪，界面能区分“仅有引用记录”“已上传未导入”“已导入”。
4. 知识库问答与商品知识预览只声明“本次提供给 AI 的依据”，不声称模型一定引用了某个来源。
5. 来源被使用时，删除操作给出真实关联对象和可行动作，不再统一提示“版本已变化”。
6. 事实、来源、规则、问答的稳定键全部由服务端生成；普通界面不要求用户理解 key、JSON 或版本号。
7. 异步加载、重复提交、并发版本、部分失败、迁移、回滚和测试基础设施都有确定行为。

## 3. 首版范围

### 3.1 包含

- 新增知识库文档、解析章节和导入关系的 SQLite 模型及幂等迁移。
- 新增文档列表、上传、详情、导入和删除 API；复用现有认证、知识库版本和 `UploadFile` 能力。
- 首版支持 `.md`、`.markdown`、`.txt`，接受 UTF-8/UTF-8 BOM，单文件最大 512 KiB。
- Markdown 按标题和段落确定性切分，纯文本按段落切分；不调用 AI 解析，不访问网络。
- 用户确认后，所选章节以事务方式导入为买家可见事实，并自动关联文档来源。
- 来源反向引用摘要、文档状态、导入条目数量和安全的问答/预览依据摘要。
- 编辑器文档工作区、上传/预览/确认导入流程、自动键、行内校验和分型错误提示。
- 账号/商品切换的过期请求防护、提交中禁用、重试和冲突刷新。
- 旧来源数据的兼容展示：没有文件实体的来源显示“仅引用记录”，不伪造文件内容。
- Python 单元/集成测试、前端合同测试、无头 Playwright E2E、类型检查和生产构建。

### 3.2 不包含

- 不支持 PDF、DOCX、图片 OCR、压缩包、网页抓取、远程 URL 下载或整仓库自动索引。
- 不引入向量数据库、embedding、全文搜索服务、外部文档处理服务或第二个数据库。
- 不把来源备注、原始文件正文、内部规则或私有知识发送到外部服务；只有用户明确导入且启用的买家可见事实可进入既有模型上下文。
- 不自动把上传内容判定为安全、公开或正确，也不自动生成规则和公开问答。
- 不修改知识库全局共享、商品绑定、订单硬安全和现有认证边界。
- 不在计划生成阶段改生产源码、运行数据库、私有 seed、远程资源或真实账号数据。

用户没有指定 PDF/DOCX、远程同步或 OCR。首版以用户举例的 README 场景为依据支持 Markdown/纯文本；其他格式需要后续单独需求与依赖评审。

## 5. 当前证据摘要

- 当前来源模型只有 `source_key/title/reference/url/notes`，不存在原始文件、校验和、解析状态或章节。
- 现有 seed 迁移根据字符串引用创建来源记录，不读取字符串指向的文档。
- 运行时快照只包含已启用事实、问答和规则，来源字段被明确排除。
- 当前运行数据中的来源均为元数据记录，已有来源关系本身有效，但不能证明文件曾被上传。
- 当前来源删除在被事实、规则或问答引用时返回 409；前端没有展示关联对象并错误归类。
- 当前只有公开问答在创建时自动生成 key；事实、来源和规则仍要求普通用户填写正则受限的内部键。
- 当前绑定请求没有请求序列或取消控制，旧响应可能覆盖新选择。
- 96 项知识库相关定向测试通过；完整 core 门禁因测试静态目录缺少 `assets` 子目录而出现同源导入错误，属于测试夹具问题，必须在发布门禁前修复。

上述证据仅记录结构和测试结果，不包含任何知识正文、真实账号或运行数据内容。

## 7. 完成定义

- 一个没有 AI 或工程知识的登录用户能完成“上传 README → 预览 → 选择章节 → 导入 → 查看已关联条目 → 预览/提问查看依据”的完整旅程。
- 仅填写标题的旧来源会明确显示“仅引用记录，未上传文件”，不会被误标为已解析或已被模型使用。
- 上传失败、编码错误、文件过大、重复文件、超限、版本冲突和来源仍被引用均有准确且可操作的提示。
- 所有创建型表单都不要求手填内部键；保存按钮只在可提交时启用，后端仍是最终校验边界。
- 文档导入是单事务、一次版本递增；失败无半导入，重复请求不会创建重复文档或事实。
- 过期异步响应不能覆盖当前账号、商品或知识库；删除/绑定操作只能作用于屏幕当前 scope。
- 来源和原始文档正文不进入模型；只有明确导入、启用且被选择的买家可见事实进入既有上下文。
- 临时数据库迁移/回滚、定向 RED/GREEN、core、E2E、类型检查、构建、API 索引和隐私检查全部通过。
