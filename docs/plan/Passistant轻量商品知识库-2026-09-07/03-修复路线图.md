# 修复路线图

[返回 README](./README.md) · [上一篇：开发规范](./02-开发规范.md) · [下一篇：测试计划](./04-测试计划.md)

## 1. 问题优先级

| 优先级 | 当前问题 | 买家/业务影响 | 目标修复 |
| --- | --- | --- | --- |
| P0 | 封号/安全问题仍交给模型自由生成 | 无法保证逐字固定回复，可能过度承诺或扩展话题 | 模型前确定性 safety 分流，零模型调用 |
| P0 | 普通模型回复可主动出现封号/安全 | 违反“未问不提” | system policy + 模型后输出拒绝与确定性回落 |
| P0 | 商业敏感问法没有本地硬拦截 | 源码、成本、凭据等可能被 prompt/上下文诱导披露 | commercial-sensitive 分流、seed 白名单、输出扫描 |
| P1 | 只有自由 prompt 和商品描述，没有商品知识 | 对具体功能、安装、激活和限制答复不稳定 | SQLite 公开知识文档 + 轻量检索 |
| P1 | 旧 prompt 把 ¥9.9 当固定月价 | 混淆原价与当前活动价 | seed/提示词统一为原价 29.9、当前 3 折活动价 9.9 |
| P1 | AI test 使用任意测试商品事实和 `test_item` | 无法证明真实商品知识生效 | test API 必须接收并验证真实 item ID |
| P1 | 无知识管理/版本 API | 后续更新只能改数据库或 prompt | 带 expected version 的 GET/PUT/import/preview |
| P2 | “客户沟通”没有独立知识库入口，知识项目也没有身份 | 运营不可见；以后增加其他项目会混淆 | 新增通用“知识库”页面，当前文档标识为“Passistant 知识库” |
| P2 | API 索引尚无知识路由 | 其他模型无法 API-first 执行 | 重建索引和全量接口目录 |

## 2. 里程碑

### M1：公开事实与不可公开边界冻结

完成条件：

- 只读核验 Passistant 当前产品清单、公开指南和唯一商品 API。
- 形成内置 seed，价格、服区、安装、激活、十一项正式功能、预载提醒和公开限制齐全。
- seed 不含源码级实现、检测规避、凭据、后台/数据库、商业数据或完整激活码。
- 旧实现上能稳定复现策略/检索测试红灯。

阻断条件：

- 商品 `1081710901648` 不唯一、不属于当前用户、非在售或实际价格不是 ¥9.9。
- Passistant 产品事实源相互冲突且无法确定当前功能。
- seed 中任何条目无法判断是否可公开。

### M2：存储与 API 合同稳定

完成条件：

- `ai_product_knowledge_documents`/`entries` 建表、索引和删除行为测试通过，空文档版本可持久化。
- 同 item 的整文档替换原子化，版本冲突为 409。
- 检索结果按 scope、分数、top-5 和 2500 字符预算稳定。
- GET/PUT/import/preview 全部验证当前用户账号和 item 归属。
- 新路由进入静态 API 索引和 Markdown 目录。

阻断条件：

- 需要依赖 FTS5/向量扩展才能正确工作。
- 只能通过直接生产 DB 写入才能导入 seed。
- 通用管理员数据接口能绕过 version 或批量清空保护。

### M3：AI 策略门禁稳定

完成条件：

- 安全问法（包括检测、反作弊、绕/规避检测）精确返回 `目前没有收到玩家反馈有封号情况出现。`，并证明模型、知识和客户端创建零调用。
- 商业敏感问法固定拒答，同样零模型调用。
- 普通问答只注入命中的公开答案，不带 source refs 和内部字段。
- 模型主动输出安全/敏感信息时被拦截，不发送原文。
- 价格回答同时说明 29.9 原价与当前 3 折活动价 9.9；拒绝额外砍价；不虚构活动结束时间。
- 既有议价底线、上下文隔离、思维链防泄露和订单事件绕过无回归。

阻断条件：

- 固定策略必须经过 LLM 才能分类或生成。
- 自定义 prompt 可绕过硬规则。
- 输出拦截只能返回 `None`，随后被现有默认回复再次泄露同类内容。

### M4：运营、部署和真实商品闭环

完成条件：

- “客户沟通”侧栏有独立“知识库”；页面当前项目显示“Passistant 知识库”，AI 回复页只负责真实商品测试。
- 知识库页能选择真实商品、导入/编辑/保存/预览，409 不覆盖。
- Python 专用/全套测试、前端生产构建、API 索引双生成、diff check 全通过。
- 容器重建后 healthy，OpenAPI 含新路由。
- 通过认证 API 给唯一商品导入 seed，GET 回读版本、数量和 checksum。
- API test 验证安全固定句、敏感拒答、非主动提及和普通知识回答。
- 未调用商品发布、创建、编辑、card/delivery 写入或真实消息发送。

## 3. 迁移路线

### 3.1 数据库

1. 应用启动执行幂等 `CREATE TABLE/INDEX IF NOT EXISTS`。
2. 初始文档 version 0、无条目；旧 AI 行为暂不改变。
3. 部署通过后用 import API 对 `1081710901648` 显式导入。
4. GET 回读 version 1、seed version、entry count 和 checksum。
5. 第二次相同 expected version 导入应 409；GET checksum 相同则证明首轮成功。

不把 `custom_prompts` 自动迁移成知识。旧 prompt 可能含过期价格或安全措辞，只能作为账号风格输入；硬策略和当前 seed 优先。

### 3.2 AI 设置

- 不改 `.env` 或 API Key。
- 保留当前已配置的 DeepSeek model/base URL/key 与上下文设置。
- 价格仍设置 `max_discount_percent=0`、`max_discount_amount=0`，表示活动价之外不再让价；这不否认商品当前活动折扣。
- 若 `custom_prompts` 仍把“9.9”描述为固定原价，执行时通过现有 AI settings API 更新该业务描述，并在 GET 回读时只检查结构/哈希，不记录完整 prompt。
- 即使未及时更新旧 prompt，新硬规则和 seed 仍必须保证最终价格口径正确。

### 3.3 API test

旧 payload：`message + item_title/item_price/item_desc`。

新 payload：`message + item_id`。服务端读取真实 `item_info`。前端与文档同步升级，不保留可以伪造商品事实的兼容分支；如果外部调用方尚未迁移，返回 422 并按 API 目录更新调用方式。

## 4. 回滚方案

| 故障 | 回滚动作 | 保留项 |
| --- | --- | --- |
| seed 某条事实错误 | GET 当前版本后 PUT 修正/停用该条 | 版本历史摘要和策略门禁 |
| 普通知识导致回复质量下降 | PUT 空 entries 或全部 disabled | safety/sensitive 固定分流 |
| 前端知识库页面故障 | 回滚 `knowledge-base` 导航与页面构建，继续用 API 管理 | 数据表、API、AI 检索 |
| AI 集成异常 | 回滚知识注入，保留硬策略或临时关闭账号 AI | 自动发货和订单链路 |
| 容器启动失败 | 保留旧 healthy 容器/镜像并恢复候选 | 数据卷中的新表和知识 |
| version 冲突 | GET 新版本，人工比较 checksum 后重试 | 不强制覆盖 |

不得通过删除整个数据库、清空所有业务表、重建商品、重生成激活码或关闭敏感门禁来回滚。

## 5. 风险与缓解

| 风险 | 概率/影响 | 缓解 |
| --- | --- | --- |
| Passistant 内部文档被误当公开知识 | 中/高 | 允许来源 + 人工白名单 + 内容扫描；运行时不扫仓库 |
| 关键词漏判变体安全问法 | 中/高 | NFKC/casefold、中文/英文用例矩阵、策略可集中扩展 |
| “后台运行”被误判商业后台 | 中/中 | 敏感规则使用短语组合，不使用单个“后台” |
| 模型忽略 prompt 主动谈安全 | 中/高 | 后置输出校验，拒绝原回复并确定性回落 |
| 价格原价/活动价混淆 | 高/高 | 单一 pricing 条目、精确回归、旧 prompt 审计 |
| “3 折”与数值比例不完全一致 | 高/中 | 用户活动宣传口径优先，回复同时给出准确金额，不自行重算文案 |
| 两个管理页面并发覆盖 | 中/中 | expected_version + 409 + GET 比较 checksum |
| 知识跨账号/商品泄露 | 低/高 | 所有查询含 cookie_id/item_id，权限与负向测试 |
| 删除商品留下孤儿知识 | 中/中 | 外键实测 + 显式删除兜底 |
| test 对话污染真实上下文 | 中/中 | test UUID 标记并清理/排除，测试覆盖 |
| 管理 API 回显来源路径 | 低/中 | response model 排除 source refs，契约测试 |
| 旧前端/调用方使用旧 test payload | 中/低 | 明确 422、同步前端和 API 目录，不做隐式假数据 |

## 6. 变更顺序与依赖

```text
失败测试 + seed 合同
    ↓
DB schema/methods
    ↓
ProductKnowledgeService
    ↓
FastAPI routes + API index
    ↓
AIReplyEngine 前置/后置门禁
    ↓
React editor + 真实 item test
    ↓
全套测试/build/container/API import
```

顺序不可打乱：AI 接线依赖稳定检索；前端依赖 API response；生产导入依赖容器已运行新 schema 和路由。

## 7. 发布门禁

以下任一项为 FAIL 时不得进入生产导入：

- 安全固定句不是逐字相等，或路径调用了模型。
- 普通问答可能主动输出封号/安全话题。
- 商业敏感问法会进入模型或返回内部事实。
- seed 敏感扫描非零、来源不明或价格口径不正确。
- 账号/商品隔离、version 409 或删除行为测试失败。
- Python 全套、前端 build、API 索引一致性或容器健康失败。
- 需要浏览器、桌面或直接 DB 才能完成导入/验证。
- API 操作清单出现商品创建/发布/编辑、卡密或发货配置写入。
