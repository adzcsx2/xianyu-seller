# 修复路线图

[返回 README](./README.md) · [上一篇：开发规范](./02-开发规范.md) · [下一篇：测试计划](./04-测试计划.md)

## 1. 问题优先级

| 优先级 | 问题 | 影响 | 目标 |
| --- | --- | --- | --- |
| P0 | Passistant 固定策略在检查商品绑定前全局分类 | 普通商品可能收到 Passistant 话术 | 运行时只加载当前商品 bindings 后的规则 |
| P0 | 当前无效 `custom_prompts` 被整段当全局 system 文本 | 价格、区服、交付等业务污染所有商品 | 业务迁入知识库；全局 style 使用新存储与纯语气 |
| P0 | iPhone 商品已有 Passistant 复制文档 | 错误商品拥有错误知识 | 幂等迁移只绑定正确商品并排除 iPhone |
| P1 | 知识内容按商品复制，没有全局库 | 无法复用、无法统一维护 | 全局 base + 多对多 binding |
| P1 | 查无文档仍伪造 Passistant identity | 所有商品看起来都有库 | bindings 空即真实空态 |
| P1 | source refs 被 API/UI 隐藏，内部规则无模型 | 无法完成全内容 CRUD 和审计 | facts/sources/rules/qa 四类管理 |
| P1 | 议价参数在账号 AI settings | 商品商业边界无法随知识绑定 | pricing/bargain 结构化规则 |
| P1 | 缺少全局 CRUD/绑定 API | 页面只能覆盖商品文档 | 新增全局资源和绑定合同 |
| P2 | 当前页面标题、按钮与删除语义不对 | 运营容易误操作 | 两段式页面、解绑/全局删除明确区分 |
| P2 | AccountList 和 AIReply 重复编辑 prompt | 设置互相覆盖 | 单一全局 style 入口，移除业务 prompt UI |
| P2 | API 索引仍是旧知识合同 | 后续模型无法 API-first | 同步 index/目录/OpenAPI |

## 2. 里程碑

### M1：合同和迁移红灯冻结

交付：

- 只读确认当前两份重复 Passistant 文档、正确/错误商品和无效旧 prompt。
- 冻结四类内容、全局 style、结构化 rule、binding 和错误语义。
- 新增测试在旧实现上因语义不满足而失败。

退出条件：REQ-001～013 均有测试或可复现证据；运行 DB hash/mtime 未变化。

阻断：无法唯一确定 `1081710901648` 的 cookie/item；seed 与用户当前改动冲突；旧 prompt 中存在需要用户裁决的新业务事实。

### M2：全局知识数据/API 可独立工作

交付：

- 全局 base、四类内容、bindings、migration marker 和单例 profile 的幂等 DDL 与事务方法。
- Passistant v2 seed、来源去重、规则校验和迁移。
- 全局 CRUD、四类内容 CRUD、binding、preview 和 style API。
- 旧商品知识写路径退出活动运行时，API 目录同步。

退出条件：临时 DB 的创建、更新、删除、级联、引用冲突、version、迁移重试和权限测试全部通过。

阻断：必须引入第二数据库或新依赖；无法把迁移与 marker 放入同一事务；通用管理员接口可绕过专用合同。

### M3：AI 无跨商品污染

交付：

- 全局 style 与账号 model/API/context 分离。
- snapshot 只读取当前商品 bindings。
- Passistant fixed/topic/pricing/bargain/output 规则结构化执行。
- 多库稳定合并和引擎硬安全分层。

退出条件：正确商品命中 Passistant；iPhone 和另一普通商品在相同问法下零 Passistant 知识/规则；订单/secret 回归通过。

阻断：未绑定路径仍读取模块级 Passistant terms；旧 custom prompt/discount 字段仍影响生成；固定规则必须调用模型。

### M4：前端完整管理闭环

交付：

- “当前项目知识库”列表和绑定/解绑弹窗。
- “全部知识库”列表、创建、打开和全局删除确认。
- facts/sources/rules/qa 四类编辑器。
- “全局回复风格”纯语气入口，删除两个页面的旧业务 prompt/议价配置。

退出条件：交互静态合同、错误/空态、409、重复点击、事件冒泡和生产构建全部通过；按受保护边界不运行浏览器自动化，视觉项记录 `not verified`。

阻断：必须引入新的前端测试/状态管理依赖；全局删除与解绑无法在 UI 文案中区分；用户改动与目标 hunk 无法安全合并。

### M5：迁移与本地运行候选通过

交付：

- 运行 DB 可验证备份。
- 临时副本两次升级、故障回滚和“删除后不重建”演练。
- Python 全套、前端 build、API index/OpenAPI/Markdown 对齐。
- 容器/API-only 回读正确绑定、四类内容、style 和 AI 零污染。

退出条件：REQ-001～013 全部 PASS；无秘密、越界 API 或无法恢复的数据写入。

## 3. 依赖顺序

```text
需求/迁移红灯
    ↓
全局 schema + marker
    ↓
Passistant v2 content/rules
    ↓
全局 CRUD + bindings API
    ↓
reply style + runtime snapshot
    ↓
AI engine rule execution
    ↓
frontend types/API/page/editor
    ↓
全量门禁 + 临时迁移
    ↓
备份 + 本地运行候选/API 验收
```

前端不得先用 mock API 独立落地；AI 不得在 binding/service 未完成时继续依赖硬编码 Passistant；运行数据迁移必须排在临时副本演练之后。

## 4. 迁移路线

### 4.1 Schema 与数据

1. 创建全局 base、四类内容、binding、profile 和 marker 表。
2. 在临时 DB fixture 上运行迁移，确认旧表不被删除。
3. 读取 v2 seed，生成唯一 Passistant base。
4. 按目标 item ID 唯一定位 cookie，并只创建一条 binding。
5. 创建纯语气的 default reply style。
6. 写 migration marker；事务 commit。
7. 二次运行应 no-op；删除新 base 后第三次运行仍 no-op。

### 4.2 运行时切换

- `AIReplyEngine` 切换到 `load_snapshot`，旧商品知识表不再读取。
- 全局 style 替代 `_resolve_system_prompt` 对旧 `custom_prompts` 的读取。
- 账号 AI settings 只保留连接、启用和上下文职责。
- 旧知识 API 写路径停止；兼容读适配若保留，只从新 bindings 聚合，不读旧表。

### 4.3 前端切换

- 先发布后端新 API 与兼容行为，再发布新前端。
- 新前端只调用全局 CRUD/bindings/style，不提交旧 prompt/discount 字段。
- 若后端回滚，新前端会缺少 API，因此容器部署必须原子使用同一构建候选。

## 5. 回滚与恢复

| 故障 | 恢复动作 | 不得做 |
| --- | --- | --- |
| 新 schema 启动失败 | 恢复旧镜像；新空表可保留 | 删除整个 DB |
| 数据迁移失败 | 事务自动 rollback，修复后重试 | 手工补 marker |
| 迁移后绑定错误 | 立即停 AI；从 online backup 恢复，修正迁移后重跑 | 手写 SQL 猜测修复 |
| 普通商品出现 Passistant | 停用新 runtime/解绑并恢复候选 | 仅改 prompt 掩盖 |
| 四类编辑器保存异常 | 保留 API，回滚前端；GET 回读版本 | force 覆盖 409 |
| 某 source 删除失败 | 先解除引用再删除 | 静默清空 source_ids |
| 全局删除误操作 | 从 P5.1 备份恢复 | 启动迁移自动重建 |
| style 内容不合适 | PUT 新 style 或恢复默认文本 | 把商品规则写回 style |
| 多库价格冲突 | 暂停议价并人工调整规则/绑定 | 让模型自行选择价格 |

备份必须在明确路径、仓库外或 ignored runtime 目录，验证可打开后才允许运行数据迁移。恢复演练只在副本，不覆盖当前运行 DB。

## 6. 风险与缓解

| 风险 | 概率/影响 | 缓解与门禁 |
| --- | --- | --- |
| migration 误把 iPhone 绑定 Passistant | 中/高 | 精确 item ID、显式负断言、临时副本演练 |
| 用户删除 Passistant 后重启被重建 | 中/高 | marker 独立于 base 生命周期，专门测试 |
| 全局库无 owner 被误做成未认证公开 API | 低/高 | 所有 route 保留 get_current_user；只移除资源所有权 |
| 重复绑定竞态 | 中/中 | UNIQUE + 409，前端 disabled 只是体验层 |
| 删除 base 影响多商品 | 中/高 | 确认显示 binding_count，事务级联和备份 |
| source 引用悬空 | 中/中 | 删除前引用检查 409，外键/领域校验 |
| arbitrary rule 覆盖安全 | 中/高 | rule type 白名单、结构校验、引擎 guard 最高优先级 |
| style 再次混入商品业务 | 高/中 | UI 提示 + 服务端业务词校验 + 默认值测试 |
| 旧 prompt 仍被隐藏路径读取 | 中/高 | 全仓静态搜索 + 未绑定/旧 prompt 非空回归 |
| 多库冲突导致错误价格 | 中/高 | 最严格组合、不可合并时拒绝议价 |
| 前端删除按钮触发 row open | 中/低 | stopPropagation + 交互测试 |
| 单资源编辑 version 冲突 | 中/中 | 每次只保存一个资源，409 后停止并 GET，不批量串行假装原子 |
| 工作区用户改动被覆盖 | 中/高 | P<N>.1 status/diff、hunk 级编辑、不 reset |
| API index 与源码漂移 | 中/中 | 双生成 + OpenAPI/JSON/MD 集合比较 |

## 7. 发布门禁

以下任一情况为 FAIL，不能迁移运行数据：

- 全局表含 owner/account scope，或全局 API 未认证。
- iPhone/普通商品出现 Passistant binding、facts、rules 或回复。
- marker 不能阻止重复迁移或删除后重建。
- source_refs 进入模型、preview、买家回复或日志。
- 旧 `custom_prompts/max_discount_*` 仍影响运行时。
- fixed rule 调用了模型；订单/secret guard 可被知识库关闭。
- duplicate binding 未由 DB 拒绝，或全局删除非事务。
- source 删除可产生悬空引用。
- Python 专用测试、前端生产 build、迁移演练或 API 索引对齐失败。
- 工作区用户改动无法分离、备份不可验证或出现秘密输出。

## 8. 完成定义

功能完成不等于 UI 能点开。最终完成必须同时满足：

- 数据：全局库、四类内容、binding、profile 和 marker 合同通过；
- 迁移：唯一 Passistant、唯一正确 binding、其他商品为空；
- 运行：绑定才生效，无绑定零污染，多库结果确定；
- 前端：两段式列表、两个删除语义、四类 CRUD 和全局 style 可用；
- 安全：来源不泄露、订单事实不虚构、固定规则零模型调用；
- 工程：专用/全套测试、build、API 文档、diff 与本地候选证据完整；
- 恢复：备份已验证，失败/误删/回滚步骤可执行。
