# 测试计划

[返回 README](./README.md) · [上一篇：修复路线图](./03-修复路线图.md) · [下一篇：测试用例清单](./05-测试用例清单.md)

## 1. 测试目标

验证重构不是页面改名，而是完整解决资源范围、数据迁移和 AI 作用域：

1. 知识库全局存在，不归账号/用户；所有已认证用户看到同一库。
2. 商品只通过 binding 使用知识；无绑定商品没有幽灵 Passistant。
3. 创建、读取、更新、删除 base 及 facts/sources/rules/qa 均可用且有版本保护。
4. 添加/删除当前商品知识库语义为绑定/解绑，重复绑定无法产生重复数据。
5. 全局删除确认后级联内容与 bindings，不误删商品。
6. Passistant 仅绑定正确 POE2 商品，错误 iPhone/其他商品初始为空。
7. 全局 reply style 是纯语气且跨账号一致；商品业务只来自绑定库规则。
8. 来源引用可管理但不会进入模型、preview、买家回复或日志。
9. 多库规则和知识合并确定、并发/重试/迁移/回滚可预测。
10. 现有订单、自动发货、AI 安全、上下文和秘密防护无回归。

## 2. 环境与隔离

- Python：现有 Python 3.11+ 与 `unittest`。
- 数据层：`TemporaryDirectory` 中的新 SQLite、旧 schema fixture 和运行 DB 的只读/backup 副本。
- AI：mock 模型客户端和生成调用；单测禁止真实 DeepSeek/外网。
- API：优先直接 handler/service + 临时 DB；如使用 TestClient，覆盖应用依赖且不能连接运行 DB。
- 前端：`frontend/package-lock.json` 对应 `npm ci` 与 Vite production build；不引入新测试依赖。
- 浏览器/桌面自动化：按上一版受保护执行边界不使用；视觉项只做静态合同和 production build，标 `not verified`。
- 运行验收：本地 compose/`http://localhost:8080`，先备份再迁移；只用认证 API 回读。
- Passistant 上游：不读写/运行。本轮事实以项目 seed 和用户确认合同为准。

## 3. 测试层级

### 3.1 Schema 与领域单元测试

验证：

- 新库建表/索引，旧表不受影响；
- base 与四类内容没有 owner/account 字段；
- key/name 唯一、字段长度、枚举、Decimal、JSON、总量和 payload 边界；
- base 聚合 version 每次内容 mutation 递增，stale write 无部分写；
- source 引用只允许同库存在 id，被引用 source 删除 409；
- binding UNIQUE、sort order、解绑、base/item 删除级联；
- foreign_keys 关闭时显式清理仍生效；
- checksum 对排序稳定、对语义内容变化敏感。

### 3.2 Migration 测试

准备旧 schema fixture：

- 正确商品 `1081710901648` 有 Passistant 文档；
- iPhone `741903197018` 有同 checksum 复制文档；
- 至少一个其他商品无文档；
- 旧 `custom_prompts` 非空且 JSON 解析失败；
- 旧折扣字段存在。

验证第一次迁移只创建一个 Passistant、一条正确 binding 和一个纯 style；第二次 no-op；事务中途异常 rollback；marker 存在后删除 base 不重建；目标商品缺失/key 冲突阻断且不写 marker。

### 3.3 Passistant v2 内容与规则

- 现有公开问答、来源和用户未提交 seed 变更完整迁移；
- sources 去重、所有 source_ids 可解析且同库；
- facts/qa 买家可见文本不含秘密/本地路径；
- fixed safety 与 topic refusal 精确、零模型调用；
- pricing/bargain 使用 Decimal，原价/活动价/无额外砍价正确；
- output guard 只在绑定商品执行；
- engine guard 不依赖可删除 Passistant rule。

### 3.4 API 合同与认证

全局库 API：

- 未认证 401；任意已认证用户 GET/POST/PUT/DELETE 同一全局资源，不检查 owner；
- 请求若包含 `user_id/owner_id/cookie_id` 等未知字段 422；
- 404、409、422、500 均不泄露 SQL/路径/内容；
- detail 管理响应含四类内容；list summary 有计数和 binding_count；
- preview 不返回 source/reference/internal config。

binding API：

- 未认证 401；非所属 cookie 403；所属 cookie 未知 item 404；
- 重复绑定 409、解绑只删 binding、全局 base 不变；
- 删除 base 返回实际 binding_count，商品记录仍存在。

### 3.5 AI runtime 单元测试

用相同消息对三类商品测试：

| scope | 预期 |
| --- | --- |
| 正确 Passistant 商品 | 加载 facts/qa/rules，执行 Passistant fixed/pricing 规则 |
| 错误 iPhone | snapshot 空，不出现 Passistant/9.9/区服/固定话术 |
| 另一普通商品 | 同上 |

另覆盖：

- bind 后下一请求生效、unbind/delete/disable 后下一请求失效；
- 两个库的稳定检索、fixed rule 排序、价格最严格组合和冲突 fail closed；
- source/reference/rule config 不进 system message；
- 全局 style 跨账号一致，旧 prompt 非空也不进入 prompt；
- fixed reply 在 client 创建前返回，模型/检索按合同零调用；
- 模型超时、空回复、敏感输出和异常 rule 的回落；
- 系统/订单事件、支付/发货/退款事实、上下文隔离和 token retry 回归。

### 3.6 前端合同与交互

静态与 build 必测：

- 精确标题“当前项目知识库”“全部知识库”；旧“当前知识项目”不存在；
- 当前列表由 bindings API 提供，不用 emptyDocument 伪造 Passistant；
- 添加/删除知识库按钮及两个不同 dialog；
- 已绑定项 disabled/“已添加”，提交中不可重复；
- 全部列表 header 添加按钮、row open、右侧删除和 stopPropagation；
- 编辑器四类 tab/section 与 CRUD 控件；
- 全局删除确认显示 binding_count，解绑确认说明保留全局库；
- dirty close、409、loading、empty、error、disabled、成功 GET 回读；
- AIReply 标签“全局回复风格”、纯风格 placeholder；
- AIReply/AccountList 无 `custom_prompts` 与议价业务输入；
- 无 `dangerouslySetInnerHTML`，无 source 注入模型 API。

键盘焦点、窄屏和真实 dialog 视觉行为标 `not verified`；事件冒泡、文案、disabled、dirty 和 409 通过静态合同验证。build/静态合同仍是硬门。

### 3.7 API 索引与文档

- 生成器收录所有新 method/path、Pydantic schema、认证、商品 scope 和副作用；
- runtime OpenAPI、`.ai/index/backend-apis.json`、`05-全量接口目录.md` METHOD/PATH 集合一致；
- 连续生成两次除允许的生成时间字段外规范化内容相同；
- 旧路由标记 deprecated/410/compat 的实际行为与目录一致。

### 3.8 迁移与本地端到端

在运行 DB backup 工作副本：

1. 第一次升级并记录新表计数、Passistant checksum、binding 和 style version；
2. 第二次升级应零变化；
3. 删除 Passistant 后再次启动，不得重建；恢复副本；
4. 注入中途失败，确认 marker/新数据全部 rollback；
5. 验证旧程序能忽略新表打开副本。

在本地候选：

1. build/restart 后 `/health` 和 OpenAPI 可用；
2. 认证 GET 全部库只有 Passistant；
3. 正确商品绑定 1，iPhone/其他商品绑定 0；
4. 正确商品 preview/AI test 使用 Passistant；普通商品相同问法不使用；
5. 临时库完成 create/content/bind/unbind/delete，结束后无残留；
6. API 调用清单无商品发布、card/delivery 写入或真实消息发送。

## 4. 输入与故障矩阵

| 类别 | 必测边界 |
| --- | --- |
| 名称/key | 空、空白、最大长度、超长、非法字符、大小写/规范化冲突 |
| 数组/内容 | 空、最大项、超项、重复、跨库 source、悬空 source |
| version | 正确、stale、负数、布尔、丢失、并发两个 writer |
| binding | 首次、重复、未知 base、disabled base、未知 item、非所属 cookie |
| delete | 空库、含四类内容、绑定 0/1/N、中途异常、重复 DELETE |
| rule | 未知 type、未知字段、空 terms、负金额、冲突价格、恶意 instruction |
| style | 默认、更新、空、超长、商品名、金额、砍价/发货/安全业务词 |
| runtime | 无库、一个库、两个库、disabled、unbind/delete 后、损坏 rule |
| migration | 一次、两次、marker 后删库、缺 item、key 冲突、中途失败 |
| UI | loading/empty/error/409、双击、关闭 dirty、删除冒泡、窄屏 |

## 5. 入口/出口标准

### Phase 1

- 入口：需求与只读证据可访问。
- 出口：新测试语义红灯；旧基线可运行；运行 DB 未变。

### Phase 2

- 入口：schema/API/rule 合同冻结。
- 出口：临时 DB 与 API CRUD、binding、migration、认证全部绿；API index 更新。

### Phase 3

- 入口：新 API/data service 稳定。
- 出口：绑定作用域、global style、多库规则和 AI 安全回归全部绿。

### Phase 4

- 入口：response/payload 不再变化。
- 出口：所有静态 UI 合同通过，production build exit 0，视觉项明确 not verified。

### Phase 5

- 入口：代码候选静态门禁全绿、备份可验证。
- 出口：迁移演练、本地候选、API 回读和 REQ-001～013 全部通过。

## 7. 完成判定

| 门禁 | PASS | FAIL |
| --- | --- | --- |
| 全局范围 | base/content 无 owner，已认证用户共享 | 按账号复制或 API 未认证 |
| 商品作用域 | 仅 bindings 决定知识/规则 | 无库仍得到 Passistant |
| 初始数据 | 正确 item=1，iPhone/其他=0 | 任何错误 binding |
| CRUD | 四类完整、version/引用/级联正确 | 静默覆盖或悬空引用 |
| 重复/并发 | UNIQUE/409/rollback | 重复行、部分写、last-write-wins |
| style | 全局纯语气、旧 prompt 不生效 | 含商品业务或按账号变化 |
| AI | 绑定规则生效，无绑定零污染 | fixed rule 调模型或跨商品 |
| 来源 | 仅管理可见 | 入模、preview、买家或日志 |
| 迁移 | marker 幂等、删除后不重建 | 重复创建或错误商品绑定 |
| 前端 | 两段式/两个删除/四类 CRUD/build | 标题/操作语义不符或 build 失败 |
| 回归 | 订单/secret/上下文/自动发货不变 | 任一关键回归 |
| 恢复 | 备份可用、演练通过 | 无可验证恢复点 |

环境确实缺失可将浏览器视觉项标 `not verified`；全局范围、错误绑定、来源泄露、迁移幂等、AI 跨商品污染、Python 专用测试和前端 build 不可豁免。

## 8. 证据保存与清理

在 [00-执行文档](./00-执行文档.md) 倒序日志记录命令、exit code、用例数量、schema/migration key、base/binding/content 计数、version/checksum、HTTP 状态和容器 health。

禁止记录 prompt 正文、买家消息、source notes、API key、密码、Cookie/token、完整激活码或运行 DB 行内容。临时 DB、测试库、测试 bindings、TestClient dependency override、后台进程和文件锁必须在 finally/tearDown 清理；失败时记录明确清理命令与残留路径，不能静默遗留。
