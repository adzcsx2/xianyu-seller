# 全局知识库与 AI 回复风格重构

[执行文档](./00-执行文档.md) · [架构设计](./01-架构设计.md) · [开发规范](./02-开发规范.md) · [修复路线图](./03-修复路线图.md) · [测试计划](./04-测试计划.md) · [测试用例清单](./05-测试用例清单.md)

## 1. 背景

当前“知识库”页面把知识文档直接复制到 `cookie_id + item_id`，不存在文档时仍返回硬编码的 Passistant 身份。因此非 Passistant 商品也会呈现一个假的 Passistant 知识项目，且无法建立一个可复用的全局知识库。

页面当前还把知识条目编辑器直接放在所选商品下，并隐藏 `source_refs` 与内部规则；这与新的产品意图不一致。新的页面要明确区分两层资源：

- “当前项目知识库”展示所选商品已经绑定的知识库，只负责添加绑定和删除绑定；
- “全部知识库”展示全局知识库，负责创建、打开、编辑和全局删除。

AI 回复配置也存在职责混合。`custom_prompts`、最大折扣比例、最大折扣金额和最大议价轮次同时承担账号风格与 Passistant 商品业务。当前数据库中的非空 `custom_prompts` 还是无效 JSON，运行时会把整段内容当普通文本追加到所有意图，导致 Passistant 的价格、区服、交付和安全规则可能污染其他商品。

## 2. 目标状态

```text
全局知识库（不属于账号）
  ├─ Passistant
  │   ├─ 买家可见事实
  │   ├─ 来源引用
  │   ├─ 内部规则
  │   └─ 公开问答条目
  └─ 未来新知识库
          │
          └─ 商品绑定（cookie_id + item_id + knowledge_base_id）

全局 AI 回复风格 ── 所有账号/商品共用语气
账号 AI 设置 ───── 模型、API、启用状态、上下文
商品业务规则 ───── 来自当前商品绑定的知识库
引擎硬安全规则 ─── 订单事实、秘密泄露和失败关闭
```

初始迁移后：

- 全部知识库只有一个 `Passistant`；
- 商品 `1081710901648` 绑定 `Passistant`；
- 当前被误写入 Passistant 文档的 iPhone 商品 `741903197018` 不绑定任何知识库；
- 其他商品同样不绑定任何知识库；
- AI 回复风格采用全局、纯语气描述，不包含价格、区服、交付、砍价或产品规则。

建议的全局回复风格：

> 语气自然、友好，略带俏皮，像真实的闲鱼卖家。优先用一到两句短句直接回答，可少量使用语气词；不要复述规则，不主动扩展买家没有询问的内容，避免客服腔、夸张承诺和连续表情。

## 3. 范围

### 3.1 包含

- 将商品级复制式知识表迁移为全局知识库、四类内容资源和商品绑定表。
- 新增全局知识库 CRUD、内容 CRUD、商品绑定/解绑和预览 API。
- 重构知识库页面为“当前项目知识库 + 全部知识库”两段式交互。
- 创建、编辑、删除买家可见事实、来源引用、内部规则和公开问答条目。
- 把 Passistant 专属回复策略、定价和议价规则迁入 Passistant 知识库。
- 把账号级 `custom_prompts` 重构为单例的全局回复风格。
- 保留现有认证；不增加管理员、所有者、角色或知识库权限模型。
- 修复无文档时伪造 Passistant 身份、重复绑定、错误商品污染和无效旧 prompt 的迁移问题。
- 补齐 Python 单测、API 合同测试、前端构建、静态 API 索引和迁移验收。

### 3.2 不包含

- 不创建或发布新的闲鱼商品，不改商品图片、标题、价格或描述。
- 不改卡密库存、自动发货、订单状态或真实买家消息发送链路。
- 不引入向量数据库、embedding、外部知识服务或第二个数据库。
- 不自动索引整个 Passistant 仓库；现有人工白名单 seed 仍是公开事实来源。
- 不建设多租户 RBAC、知识库所有权、分享审批或账号级知识库隔离。
- 不在本轮计划生成阶段修改生产源码、运行 SQLite、容器或 AI 设置。

## 6. 当前只读证据

- 当前 schema 以 `(cookie_id,item_id)` 作为知识文档主键，并把条目重复保存到商品 scope。
- 当前无文档回读仍填充 `passistant / Passistant 知识库`，形成幽灵知识库。
- 当前管理 API 删除 `source_refs`，前端也明确说明来源引用和内部规则不会显示。
- 当前运行库存在两份内容相同的 Passistant 文档：正确的 POE2 商品 `1081710901648` 和错误的 iPhone 商品 `741903197018`。
- 当前账号存在一个非空且无法解析为 JSON 的 `custom_prompts`；引擎会把整段 Passistant 业务文本当通用 prompt。
- 当前 API 索引被工作区改动标记为 stale；实现阶段必须从源码重建并核对。
- 当前工作区有用户未提交修改。执行阶段不得重置、覆盖或顺手格式化这些改动。

## 7. 完成定义

只有同时满足以下条件才可宣告完成：

- 页面两段式结构、所有弹窗和四类内容 CRUD 均符合本轮文案与行为。
- 数据库中知识库不含 `user_id/cookie_id` 所有权，商品绑定有唯一约束。
- Passistant 只绑定正确商品，错误 iPhone 和其他商品为空。
- 旧 Passistant 业务 prompt 已被结构化迁入 Passistant 知识库；全局回复风格不含业务规则。
- 未绑定知识库的商品不会触发 Passistant 固定回复、价格保护或知识检索。
- 来源引用可在管理页面增删改查，但不进入模型和买家回复。
- 内部规则可管理，硬规则由服务端确定性执行，不能仅依赖模型服从。
- 专用测试、全量 Python 回归、前端生产构建、API 目录一致性和迁移回读通过。
- 没有修改 Passistant 上游仓库、生产秘密、卡密/发货或商品发布资源。
