# 聊天模式与独立功能开关

[执行文档](./00-执行文档.md) · [架构设计](./01-架构设计.md) · [开发规范](./02-开发规范.md) · [修复路线图](./03-修复路线图.md) · [测试计划](./04-测试计划.md) · [测试用例清单](./05-测试用例清单.md)

## 1. 背景与结论

当前程序在账号 WebSocket 连接建立后，会同时启动 Token 定时刷新、浏览器 Cookie 刷新、商品同步、订单同步、商品擦亮、发货超时检查和买家互动等任务。收到订单卡片时，还会在普通聊天回复之前提取订单号、查询成交数据和订单详情，并可能进入自动发货。这意味着“只打开聊天页面”并不等于“后台只运行聊天”。

现有 `global_config.yml` 把 `TOKEN_REFRESH_INTERVAL` 实际配置为 `3600` 秒，所以稳定连接也会约每小时主动请求一次 MTOP Token，并在刷新成功后主动断开 WebSocket 重连。浏览器 Cookie 刷新间隔实际为 1200 秒。Token 获取、订单/商品接口、自动发货和其他主动请求都可能增加平台验证概率；聊天连接本身也不能保证永远不触发平台风控，因此本计划的目标是减少不必要请求，而不是承诺“零滑块”。

目标架构是“聊天核心常驻 + 可选业务逐项开关 + 后端硬门禁 + 前端同源隐藏”：

- 保留账号连接、WebSocket 注册、心跳、手动收发消息和本地暂停清理；
- 关闭周期 Token 刷新后，不再每小时主动刷新，但首次连接、重连且 Token 缺失/过期、认证失败恢复仍可按需刷新；
- 商品、订单、自动发货、自动回复、AI、知识库、卡密、商品自动化及各主动后台任务都有独立 Boolean；
- 设置页新增“功能区”，一次原子保存所有功能开关；
- 保存成功后，后端立即收敛运行任务，前端立即隐藏被关闭的菜单、页面和局部操作；
- 自动评价、求花、确认收货致谢继续以每个账号现有配置为准。总开关关闭时只阻止执行，不覆盖或删除三个账号级值。

## 2. 推荐聊天模式

### 2.1 始终保留的核心

| 能力 | 状态 | 原因 |
| --- | --- | --- |
| 账号管理 | 保留 | 登录、Cookie 更新、人工验证和重连恢复的必要入口 |
| WebSocket 连接与注册 | 保留 | 收取聊天消息的基础；注册时仍需要有效 Token |
| 心跳 | 保留 | 维持聊天连接 |
| 消息中心与手动发送 | 保留 | 本轮核心目标 |
| 本地暂停记录清理 | 保留 | 只清理本地状态，不访问闲鱼接口 |
| 系统设置、通知与日志、关于 | 保留 | 可恢复开关并观察风控/运行状态 |

### 2.2 建议关闭的可选能力

| 配置键 | 推荐值 | 关闭后的有效行为 |
| --- | ---: | --- |
| `feature_items_enabled` | `false` | 隐藏商品与发货页，商品 API 动作拒绝执行 |
| `item_sync_enabled` | `false` | 不启动/停止商品同步任务 |
| `auto_polish_enabled` | `false` | 不启动/停止定时擦亮，隐藏相关操作 |
| `feature_orders_enabled` | `false` | 隐藏订单页；收到聊天内订单卡片时不再查成交数据或订单详情 |
| `order_sync_enabled` | `false` | 不启动/停止订单同步任务 |
| `delivery_timeout_alert_enabled` | `false` | 不轮询待发货超时订单 |
| `auto_delivery_enabled` | `false` | 不处理付款触发、免拼和自动发货；相关动作 API 返回功能已关闭 |
| `feature_cards_enabled` | `false` | 隐藏卡密库存页 |
| `feature_buyer_interaction_enabled` | `false` | 隐藏买家互动页并阻断评价/求花/致谢执行，但保留账号级三个值 |
| `feature_auto_reply_enabled` | `false` | 隐藏自动回复页，不调度防抖自动回复；手动聊天不受影响 |
| `feature_ai_reply_enabled` | `false` | 隐藏 AI 回复页并阻止 AI 自动回复/测试动作 |
| `feature_knowledge_base_enabled` | `false` | 隐藏知识库页并阻止知识库管理动作 |
| `feature_product_automation_enabled` | `false` | 隐藏商品自动化页并阻止相关动作 |
| `account_profile_auto_sync_enabled` | `false` | 连接成功后不自动拉账号资料；手动刷新仍保留 |
| `scheduled_token_refresh_enabled` | `false` | 不启动每小时 Token 刷新任务；连接按需刷新仍保留 |
| `browser_cookie_refresh_enabled` | `false` | 不启动周期浏览器 Cookie 刷新；扫码/密码/人工恢复仍保留 |

以上是“推荐值”，不是迁移时强制覆盖值。升级时必须保留已有数据库配置；执行完成后再通过功能区按本表保存当前部署的聊天模式。

## 3. 范围

### 3.1 包含

- 在现有 `system_settings` 上建立强类型功能开关注册表，不新增第二套持久化系统。
- 新增管理员专用 `GET /feature-flags` 和批量原子 `PUT /feature-flags`。
- 统一返回 configured/effective 状态、依赖关系和前端显示元数据。
- 动态启动、取消和重启各账号的可选后台任务，不要求重启整个服务。
- 在消息处理入口阻断订单详情拉取、自动发货、买家互动和自动回复等事件路径。
- 在相应业务 API 增加服务端门禁，避免隐藏页面后仍能直接调用动作接口。
- 设置页新增“功能区”，支持逐项 Boolean 配置、依赖说明、保存失败回滚和保存成功事件广播。
- Sidebar、App 页面渲染和各页面局部动作基于同一份 feature snapshot；处理 localStorage 中已被禁用的旧页面。
- 保留自动评价、求花、确认收货致谢三个账号级配置及模板，不做清零迁移。
- 增加数据库、API、运行时、前端合同、构建和回归测试。

### 3.2 不包含

- 不尝试规避、破解或自动绕过闲鱼风控；不承诺只聊天必然不出现滑块。
- 不移除首次连接/重连所必需的 Token 获取、人工滑块、扫码和密码登录恢复链路。
- 不修改真实账号当前的三个买家互动值，不写运行 SQLite，不启动真实闲鱼请求。
- 不删除被关闭功能的数据、卡密、订单、商品、知识库、模板或账号配置。
- 不引入新的数据库、消息队列、前端状态库或远程配置服务。
- 不在计划生成阶段实现代码、构建镜像、部署、push 或创建 PR。

## 6. 完成定义

- 功能区能读取和原子保存所有列出的 Boolean；未知键、非布尔值和越权请求被拒绝。
- 保存成功后，页面/菜单立即隐藏；当前页被关闭时跳转到 `messages`，且刷新后不会由旧 localStorage 恢复隐藏页。
- 关闭后台功能后，相应 task 被取消且不会在下一次 WebSocket 重连时重建。
- 关闭周期 Token 刷新后，稳定连接超过一个配置周期也不发起定时 Token 请求；首次连接和必要重连仍可按需获取 Token。
- 关闭订单功能后，订单卡片仍可作为聊天消息被安全忽略，但不会拉取成交数据、订单详情或触发发货。
- 关闭自动发货后，付款提示、免拼卡片和手工动作 API 均不能触发发货。
- 买家互动总开关关闭时，评价、求花、致谢均不执行，三个账号级值和模板原样保留；重新打开总开关后按原值恢复。
- 关闭只是可见性与执行门禁，不删除业务数据。
- 定向测试、核心回归、前端生产构建、API 索引一致性、`git diff --check` 和聊天模式人工验收全部通过。
