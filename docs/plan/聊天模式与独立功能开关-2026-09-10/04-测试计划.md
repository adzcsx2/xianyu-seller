# 测试计划

[返回 README](./README.md) · [上一篇：修复路线图](./03-修复路线图.md) · [下一篇：测试用例清单](./05-测试用例清单.md)

## 1. 测试目标

本计划优先证明以下事实：

1. 功能开关严格、原子、可恢复，且不会改写账号级买家互动配置。
2. 关闭后对应平台调用次数为 0，不能只证明页面看不见。
3. 周期 Token 刷新关闭后不再每小时运行，但聊天首次连接和必要重连仍能按需刷新。
4. 前端使用服务端已保存 snapshot，成功立即隐藏，失败不隐藏，刷新和旧 localStorage 不能绕过。
5. 既有人工滑块、指纹、聊天、订单安全和数据库迁移回归不退化。
6. 最终界面、包、容器和分发元数据统一为“闲鱼卖家”/ `xianyu-seller` / `adzcsx2`，旧维护者服务不再被默认调用。
7. 根 README 只保留一条直接上游 fork 声明，其他旧名称、作者、仓库、域名和统计材料没有残留。

测试不用于证明闲鱼永不风控；真实风控是平台外部状态。验收措辞只能是“已关闭的主动请求未发生”。

## 2. 测试环境与数据安全

| 层级 | 环境 | 数据 | 外部网络 |
| --- | --- | --- | --- |
| 单元/数据库 | Python unittest + `tempfile` SQLite | 合成账号/设置 | 禁止 |
| API 合同 | FastAPI handler/TestClient 或项目既有调用方式 | mock DB、假管理员 | 禁止 |
| asyncio 运行时 | `IsolatedAsyncioTestCase` | fake XianyuLive/task/API | 禁止 |
| 前端静态合同 | Python 读取 TSX/TS 源码 | 无业务数据 | 禁止 |
| 前端构建 | `npm --prefix frontend run build` | 无业务数据 | 依赖已安装后离线可运行 |
| 本地浏览器 E2E | `python Start.py` + snapshot DB + 平台 mock | 合成设置 | 禁止连接真实闲鱼 |
| 最终真实验收 | 专用测试账号 | 最小普通聊天 | 仅 Phase 4，经用户允许的目标账号 |
| 品牌/README 验收 | tracked 源码 + 临时 DB + Vite 生产构建 | 合成旧默认和自定义 URL | 禁止调用旧维护者服务 |

不得把运行 `data/` 复制进测试仓库、日志或截图。测试产物统一进入已忽略的 `logs/test-artifacts/`，所有账号 ID、URL、Token、Cookie、消息正文和订单号脱敏。

## 4. TDD 顺序

### 4.1 RED

- Phase 1 先建立不存在 registry/原子 API 的语义失败。
- Phase 2 先证明旧实现关闭配置后仍会创建 task、拉订单或触发发货。
- Phase 3 先证明旧静态 Sidebar、`hidden` section 和逐键 Promise 不满足要求。
- Phase 5 先证明旧界面/发布身份仍存在、旧服务空值仍 fallback、根 README 上游信息重复；旧 token 在测试中用分段字面量构造。

每个 RED 必须记录：命令、失败 test method、期望与实际。以下不算有效红灯：ModuleNotFoundError、TS 语法错误、fixture 路径错误、网络超时、真实账号风控。

### 4.2 GREEN

只实现让当前语义测试通过的最小生产代码。每个 Phase 先跑精确模块，再跑 core；不在红灯阶段修改生产源码。

### 4.3 REFACTOR

仅在绿灯后抽取 registry/helper/reconcile；重构后重新运行受影响定向测试、core 和 `git diff --check`。不得借重构整文件格式化用户改动。

## 5. 分层覆盖

### 5.1 Registry 与数据库

覆盖：

- key 完整、有序、无重复、依赖存在且无环；
- HTTP strict bool 与 DB 兼容 bool 的区别；
- configured/effective 多级依赖；
- existing value 优先、missing key 兼容默认、二次启动幂等；
- partial patch 事务合并、revision 递增、过期 revision 冲突；
- 第 N 项写入异常时前 N-1 项 rollback；
- 关闭/开启不改变 interval/template/business rows；
- `cookies` 三项互动值在所有 feature 更新前后相等。

### 5.2 API

覆盖：

- GET 对所有已认证用户开放且只返回非敏感 feature 合同，PUT 仅管理员；
- GET 不泄露其他 system settings；
- PUT 空 patch、unknown key、字符串 Boolean、数字 Boolean、extra field；
- 409 revision 冲突不覆盖；
- 成功返回完整 canonical snapshot、changed keys、runtime status；
- 通用逐键路由对 feature key 拒绝，对普通设置仍兼容；
- feature disabled 动作的 HTTP/code/feature/message 稳定；
- 门禁发生在 mock 领域/平台函数之前。

### 5.3 task 生命周期

每个可选 task 至少共享参数化用例：

| 场景 | 断言 |
| --- | --- |
| false 初连 | task 从未创建 |
| false -> true | 创建一次，引用有效 |
| true 重复保存 | 不重复创建 |
| true -> false | cancel、await、引用清空 |
| 取消超时 | 返回 failed/pending，调用前二次 gate 仍阻止副作用 |
| WebSocket 重连 | disabled task 不复活，enabled task 不重复 |
| shutdown | 无 pending task warning |

heartbeat 和 pause cleanup 作为负向控制：无论可选 flags 如何变化，它们均保持运行。

### 5.4 消息和动作门禁

使用合成消息 fixture：普通消息、付款提示、订单卡片、免拼卡片、交易成功、评价提醒。Mock：

- `fetch_order_real_values`
- `fetch_order_detail_info`
- `_handle_auto_delivery`
- `auto_freeshipping`
- `send_post_receipt_thanks`
- `trigger_buyer_interactions_now`
- `_run_buyer_interactions`
- `_schedule_debounced_reply`
- `send_msg`

关闭时目标调用必须为 0；打开时用最小 happy path 验证为 1。普通消息必须仍进入消息中心/手动发送路径。

### 5.5 Token 与 Cookie

- `scheduled_token_refresh_enabled=false`：`main/reconcile` 不创建 loop；推进 fake clock 超过 3600 秒，稳定连接不调 `refresh_token`。
- 首次 `current_token=None`：`init` 调一次并完成注册。
- 重连且 token stale/认证失败：按需调一次，不进入每分钟重试风暴。
- manual captcha required：沿用既有短路，不让周期 loop生成新 challenge。
- `browser_cookie_refresh_enabled=false`：不创建 browser loop；手动扫码/密码/人工接口仍能调用。
- `account_profile_auto_sync_enabled=false`：连接不自动拉；手动 refresh route 不受影响。

### 5.6 前端

静态合同至少断言：

- `SettingsSection` 包含 `features` 和“功能区”；
- feature 保存调用 `updateFeatureFlags`，不调用逐键 `updateSystemSettings`；
- 存在 `FeatureFlagsProvider/useFeatureFlags`，App/Sidebar/Settings 共用；
- Sidebar 按 visiblePageIds 过滤并删除空组；
- App 对禁用页条件 mount，不是仅 `hidden`；
- fallback 包含 `messages` 和覆盖 `active_page`；
- 买家互动保留文案存在；
- 所有 registry key 在功能区有映射。

动态本地 E2E 验证：开关当前页、保存失败、刷新、前进后退、重新开启和依赖未满足提示。

### 5.7 品牌、外链与 README

静态合同扫描所有 tracked 第一方文件并验证：

- `App.tsx`、`Sidebar.tsx`、`About.tsx`、前端源 HTML、构建后的 `static/index.html` 和 bundle 只显示“闲鱼卖家”；
- npm 根 package、app-shell、Docker 镜像/容器、GHCR、OCI labels、Actions 注释、Worker/User-Agent 使用规范身份；
- About 的开源仓库链接是 `https://github.com/adzcsx2/xianyu-seller`，没有无替代官网/邮箱；
- 旧 fork 统计资产、更新脚本/工作流和悬挂引用不存在；
- 历史文档不再保存旧机器 slug 的绝对目录或旧容器名；
- `LICENSE` hash 与 P5.1 基线一致，依赖 lockfile 的第三方作者/赞助链接未被批量替换；
- 根 README 标题、clone/release/issue/GHCR 均为目标身份，直接上游只在唯一 fork 语句中出现。

服务迁移使用临时数据库与 HTTP spy：

- 新库公告、AI 和商品详情服务均为空/禁用，不发请求；
- 精确旧默认升级后为空/禁用；
- 相似但不相等的 URL、自定义 URL、尾部路径不同 URL 均逐字保留；
- 迁移二次执行幂等，不重复 revision 或日志；
- 前端留空时显示“未配置”，不回退旧常量。

## 6. 并发与失败注入

| 场景 | 注入方式 | 预期 |
| --- | --- | --- |
| 两管理员基于同 revision 保存 | 两个请求顺序提交 | 首个 200，第二个 409，无覆盖 |
| DB 第 2 项更新失败 | mock cursor/helper 抛异常 | 所有键/revision 不变 |
| manager loop 未启动 | manager `None` 或 loop false | DB 保存成功，runtime pending |
| 一个实例 reconcile 抛错 | fake instances 一成一败 | 成功实例收敛，响应列出失败账号脱敏摘要 |
| task 正在外部调用 | async event 卡住 | 取消有超时；下一次调用前 gate 为 false |
| 前端保存响应丢失 | mock 网络错误 | 全局 snapshot/UI 不变，草稿保留 |
| 前端 409 | mock stale revision | 重新加载服务端状态并提示冲突 |

## 8. 人工浏览器验收

在本地 snapshot DB 和平台 mock 下：

1. 管理员登录，打开“系统设置 > 功能区”。
2. 打开订单页后关闭 `feature_orders_enabled` 并保存。
3. 断言立即跳到消息中心、订单菜单消失、DOM 中 OrderList 未 mount。
4. 刷新浏览器，订单仍不可见，`active_page` 为 `messages`。
5. 模拟 PUT 500，修改商品开关并保存；断言错误提示出现，商品页不被隐藏。
6. 制造 stale revision，断言 409 后 reload，不覆盖服务端新值。
7. 关闭父模块但保留子 configured=true，断言功能区显示“当前不生效”；重新开父模块，子值仍 true。
8. 关闭买家互动总开关，断言页面隐藏；重新开启后账号三项开关值不变。
9. Phase 5 构建后检查登录页、桌面/移动页头、Sidebar、About、浏览器 title 和公告管理页，只显示“闲鱼卖家”。
10. 点击 About 仓库链接，确认目标 URL 正确；官网/邮箱无替代值时不存在。
11. 在空公告/AI/商品详情地址下触发相关 UI，确认显示未配置且 HTTP spy 调用为 0。

## 9. 测试账号最终验收

仅 Phase 4、自动门禁全绿后执行：

- 保存推荐聊天模式并记录 revision/changed keys；
- 确认运行实例只有 heartbeat、pause cleanup 和必要聊天 task；
- 接收普通消息并手动回复；
- 观察当前 Token 周期，确认 scheduled token task 不存在且无定时刷新日志；
- 用无真实交易副作用的回放或测试事件验证订单/发货调用为零；
- 核对人工验证码恢复可达；
- 核对账号级评价、求花、致谢三值前后相等且在用户当前配置下保持关闭。

若无法安全获得订单卡片，不制造真实订单；使用自动测试证据并把该人工项标为“不适用/由 mock 覆盖”，不得为追求全绿扩大外部动作。

## 10. 入口与出口条件

### 10.1 入口

- P1.1 完成并记录用户改动；
- 测试使用 snapshot/temp DB；
- 所有 feature key/依赖/UI target 已冻结；
- 不存在未说明的真实账号调用。
- 进入 Phase 5 前，Phase 1～4 全部完成且功能行为已冻结；P5.1 已记录 LICENSE hash、旧身份清单和所有待删资产引用。

### 10.2 出口

- 05 中 P0/P1 自动用例全绿；人工不可安全执行项有明确替代证据；
- 关闭路径平台 mock 调用为 0；
- 核心聊天、按需 Token 和人工恢复回归通过；
- 原子 API、revision、前端失败行为通过；
- 账号级互动值和业务数据未变化；
- all/coverage/quality、前端 build、API catalog、diff check 通过；
- 品牌身份测试、旧服务精确迁移测试、README 唯一 fork 行和零残留扫描通过；
- `static/` 来自本次 Vite 生产构建，目标 GitHub/镜像/作者元数据一致，LICENSE hash 不变；
- 执行日志有命令、结果、commit 和脱敏证据。

## 11. 证据保存

每个 Phase 的执行日志至少记录：

- 精确命令和 exit code；
- 测试总数/失败数；
- RED 的语义失败摘要与 GREEN 结果；
- DB 前后 hash/mtime 或临时 DB 路径说明；
- feature revision、changed keys、runtime apply 摘要；
- task 名称和调用计数，不记录秘密；
- 浏览器验收步骤和脱敏截图路径；
- 品牌扫描命中数、唯一 fork 行位置、目标身份命中矩阵、LICENSE 前后 hash；
- 旧服务迁移仅记录 setting key、旧默认/自定义分类和结果，不保存完整 URL；
- 未执行项与原因。
