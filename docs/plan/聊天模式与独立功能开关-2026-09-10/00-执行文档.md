## 恢复协议

1. 读取进度指针，确认 Phase、状态、唯一 `next_action`、blockers 和当前 commit。
2. 完整读取本目录七份文档，跳到对应 Phase，从第一个未勾选的 `P<N>.<M>` 开始。
3. 每完成一个任务立即勾选、更新 UTC 指针，并把命令、结果和脱敏摘要插入“执行日志”顶部。
4. 只有当前 Phase 的全部任务、验收标准和阶段命令均通过，主执行代理才能把 Phase 标为 `completed` 并进入下一 Phase。
5. 失败先记录精确命令、失败用例和影响。能在本任务范围内修复则修复并重跑；无法安全推进时设为 `blocked`，停止并报告。
6. 不得 reset、checkout、覆盖或整文件格式化用户已有改动。重叠文件必须逐 hunk 审计；无法区分归属时停止。
7. 不得把关闭功能等同于删除配置。任何迁移、回滚或运行时收敛都必须证明账号级和业务级配置仍可恢复。
8. 功能区保存成功后，以后端返回 snapshot 为唯一前端状态；不得用请求前的本地草稿假装保存成功。

## 不可变约束

- 聊天核心包括账号连接、WebSocket 注册、心跳、手动收发消息和本地暂停清理，不能被可选业务开关误伤。
- 首次连接、Token 缺失/过期、重连认证失败时仍允许按需调用 `refresh_token`；`scheduled_token_refresh_enabled=false` 只禁止周期任务。
- 人工滑块、扫码登录、密码登录、手动刷新资料和手动恢复 Cookie 是恢复路径，不受后台周期刷新开关阻断。
- 每个可选功能必须拥有独立 Boolean 配置。父模块关闭时 `effective=false`，但 configured 子值原样保留；重新打开父模块按旧值恢复。
- `system_settings` 是系统级功能开关的唯一持久化层；不得再建立 JSON 文件、环境变量或第二张配置表作为竞争事实源。
- 自动评价、求花、确认收货致谢继续使用 `cookies.auto_rate_enabled/auto_flower_enabled/auto_thanks_enabled`。功能总开关只能门禁执行和页面，不得写回这三列。
- `AUTO_REPLY_ENABLED`、`AUTO_DELIVERY_ENABLED` 等历史环境变量不能继续与数据库争夺运行时控制权；兼容期只能用于“数据库缺键时的默认解析”，不得覆盖已保存值。
- 所有功能开关写入必须经过白名单、严格 Boolean 校验和单事务批量提交；未知键或部分失败时整批不变。
- 前端隐藏不是安全控制。关闭的服务端动作路由和运行时事件入口必须 fail closed，返回稳定 `409 feature_disabled`，GET 配置与恢复入口除外。
- 保存后的运行时任务收敛必须幂等：重复保存不重复建 task，关闭后不残留 task，WebSocket 重连不把已关闭 task 拉起。
- 关闭功能不删除商品、订单、卡密、知识库、模板、日志或任何账号配置。
- 日志只记录 feature key、old/new Boolean、账号 ID 的脱敏标识和收敛状态；不得输出 Cookie、Token、验证码 URL、聊天正文或卡密。
- 真实闲鱼风控不可由本项目保证。验收只能证明“不再执行已关闭请求”，不能宣称“永不出现滑块”。
- 计划执行期间不 push、不创建 PR、不改 remote；是否提交本地 commit 由用户另行决定。
